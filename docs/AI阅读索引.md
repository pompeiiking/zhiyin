## 五、给 AI 的硬规则

1. **不重新定义架构或业务口径**。要偏离，先改对应权威文档并留痕，再动代码。
2. **存储分工不许自创**：业务权威库＝MySQL（pami 实例、schema `zhiyin_service`）；向量库＝PostgreSQL + pgvector（独立实例、库 `zhiyin_vector`）；全文检索＝ES；缓存＝Redis；事件＝Kafka；对象＝MinIO。全部复用 pami，**职引唯一新增的是 pgvector**。
3. **依赖放对层**：该由基础设施层提供的依赖就放在 pami 模块内，不在职引侧自建（例：嵌入模型走 pami 模型服务，不自托管）。
4. **改字段的固定链路**：后端 DTO → 导出契约快照 → 生成前端类型。少一步门禁就红。
5. **共享写点不直接改**：`api/dto/mappers.py`、`boot/container/services.py`、`data/registry/ownership.json`、`contracts/openapi.json`、`zhiyin-web/src/api/types.ts`，走请求而非并行修改。
6. **跨分支注意**：`develop` 是集成线、`main` 是发布线。本套文档与 `docs/数据全链路/*` 目前只合入了 `develop`，`main` 尚未合入。
7. **合并前门禁**（在 `zhiyin-src/template` 下）：`python -m pytest -q`、`python -m ruff check .`、`python scripts/export_openapi.py --check`、`python -m zhiyin_boot --check`、`cd zhiyin-web && npm run typecheck`。
