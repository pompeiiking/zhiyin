# Wanwu 外部程序真实 API 契约（字段级）

> 本文档不是接口示例目录。它将测试脚本实际发送的请求与 `results.json` 结果映射到接口，并用当前仓库 Swagger、源码路由补全全部字段。生成命令：`node scripts/generate-real-api-contract.mjs`。

## 1. 全局调用规则

- 管理接口：`Authorization: Bearer <JWT>`、`X-Org-Id: <ORG_ID>`。
- RAG/智能体运行接口：`Authorization: Bearer <APP_API_KEY>`。
- JSON 请求：`Content-Type: application/json`；上传接口按字段表使用 `multipart/form-data`。
- 成功必须同时满足 HTTP 2xx 且 JSON `code === 0`。
- 状态口径：✅ 表示只有成功记录；⚠️ 表示同一接口既有成功也有失败/跳过；❌ 表示有失败且没有成功；⏸ 表示全部跳过；○ 表示测试脚本未执行。
- “请求格式依据”为“测试脚本实际请求”时，表示本轮确实发送过该方法和路径；未执行项的字段只能视为 Swagger/源码契约，不能当作已经跑通。
- 表中“必填”严格来自当前 Swagger `required`；Swagger 未标必填但服务端校验需要的情况，在说明中另行注明。
- JSON 块是按当前 schema 生成的可发送结构：键名和层级是真实契约，`<...>` 只表示需要替换的值，不是用“等”省略的示例。

### OpenAI 兼容模型 `config` 真实结构

LLM：`{"apiKey":"<KEY>","endpointUrl":"http://host.docker.internal:18080/v1","functionCalling":"toolCall"}`。Embedding/Rerank：`{"apiKey":"<KEY>","endpointUrl":"http://host.docker.internal:18080/v1"}`。`functionCalling` 可选 `noSupport | toolCall | functionCall`。

## 5. 已知契约/服务问题

- `PUT /user/api/v1/resource/permissions`：当前返回 HTTP 403 / code 110003 / `EOF`，请求体被 Record 中间件先读取且未恢复。
- `PUT /user/api/v1/org/status`：子组织启停可触发 nil-pointer panic。
- `GET /user/api/v1/api/category/info`：`SearchKnowledgeInfoReq.OrgId` 缺少 `form:"orgId"`，GET query 无法绑定。
- `POST /workflow/api/node/run_python`：当前节点请求返回 `input param type is NoneType`。
- `/bffservice/v2/app/list`：当前部署返回 404。
- `/callback/v1/model/*`：Nginx 默认不向外部业务网络开放，只应用于可信内部服务。

## 6. 已修复契约问题

- 2026-09-13：`GET /user/api/v1/assistant`在本地智能体 `externalConfig` 为空时曾返回 HTTP 200 空正文。BFF 现已将空值规范化为 JSON `null`；智能体 4/5 均回归为完整 JSON、`code:0`。
- 2026-09-13：智能体试运行、应用广场和 OpenAPI Agent Chat 共用的底层 Action 链路曾因 `[ACTION]` 配置不存在、错误网关地址、内部模型回调误走占位鉴权，以及“无需工具”分支清空正文而无法正常回答。现已做临时修复；使用本地模型 8 和测试插件端到端回归得到 HTTP 200、`qa_type:20`、非空正文及 `finish:1`。详细启动和限制见通俗接入手册。

## 7. 资源授权适用范围

`resourceType` 仅支持 `model`、`agent`、`workflow`、`knowledge`、`mcp`。RAG 应用不是该表中的独立类型，它通过应用所有者、组织、发布状态和 API Key 控制运行访问。
