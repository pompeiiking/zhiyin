# Wanwu 系统上下文与功能架构

## 1. 系统边界

Wanwu 是企业级 AI 应用开发与运营平台。系统边界内包含模型、知识、工具、智能体、RAG、工作流、应用发布与组织权限的管理面，以及部分 Agent 执行能力；模型推理、联网数据、MCP 工具和可选外部智能体属于边界外服务。

```ascii
                   +-------------------- Wanwu 平台边界 --------------------+
+----------+       |  Web/Nginx -> BFF -> 领域微服务 -> AI 执行引擎         |       +----------------+
| 管理员    |------>|  配置模型、组织、知识、工具、应用、权限与发布           |------>| 模型提供商       |
+----------+       |                                                        |       +----------------+
+----------+       |                                                        |       +----------------+
| 应用开发者 |------>|  构建 Agent、RAG、Workflow，调试并发布                 |------>| MCP/搜索服务     |
+----------+       |                                                        |       +----------------+
+----------+       |                                                        |       +----------------+
| 最终用户  |------>|  对话、运行工作流、使用应用广场                         |<----->| 企业业务系统     |
+----------+       |                                                        |       +----------------+
+----------+       |  外部智能体适配与嵌入【未提交】                          |       +----------------+
| API 调用方 |<---->|  OpenAPI / API Key / Callback                         |<----->| 外部Agent平台    |
+----------+       +--------------------------------------------------------+       +----------------+
```

## 2. 参与者与权限目标

| 参与者 | 主要行为 | 安全边界 |
|---|---|---|
| 管理员 | 组织、用户、角色、模型和平台配置 | JWT、组织上下文、菜单/接口权限 |
| 应用开发者 | 创建知识库、RAG、Agent、工作流、MCP 并发布 | 资源归属；成员授权【未提交】 |
| 最终用户 | 消费已发布应用和自己的会话 | 应用/API Key/资源可用权限 |
| 外部调用方 | 通过 OpenAPI 调用模型或应用 | API Key、路由隔离、限额配置 |
| 运维人员 | 部署、配置、日志、备份和健康检查 | 主机、Compose、密钥文件权限 |

## 5. 关键用户旅程

### 5.1 创建知识增强智能体

1. 管理员导入 Chat、Embedding、Rerank 模型。
2. 开发者创建知识库并上传文档；Knowledge 服务提交解析/索引任务给 RAG 引擎。
3. 开发者创建智能体，绑定模型、知识库、MCP/Action 和提示词。
4. Assistant 服务保存配置，运行时调用 Python Agent；回答通过 BFF 以 SSE 返回。
5. 开发者发布到应用空间/广场，或获取开放调用入口。

### 5.2 构建工作流

1. Web 使用 X6 画布编排开始、模型、RAG、API、代码、MCP、条件、文件和结束节点。
2. 工作流配置发送到 AgentScope；模型调用可回到 BFF OpenAI 兼容入口。
3. 调试结果流式返回，发布后可由平台应用或工作流 API 运行。
4. 成员执行共享工作流时，当前工作区通过成员授权补丁过滤与校验【未提交】。

## 6. 外部依赖

| 依赖 | 用途 | 平台责任边界 |
|---|---|---|
| 模型 API | Chat、Embedding、Rerank | 管理连接配置；不保证供应商可用性 |
| MCP Server | 工具发现与调用 | 保存协议配置；工具权限仍由 MCP 端负责 |
| 联网检索 | 实时搜索 | Agent 调用；内容质量由外部来源决定 |
| 外部 Agent 平台【未提交】 | Dify、Agno、LangServe、LangGraph、通用 HTTP | 适配请求/响应；远端会话与任务终止由对方负责 |
| 企业系统 | OA/CRM/ERP 等 | 通过 API、Callback、MCP 或工作流节点集成 |

## 7. 范围外事项

- 当前 Compose 不提供跨主机高可用编排。
- 平台不接管外部 iframe 页面的登录、Cookie、CSP 或数据合规。
- 成员授权只授予资源使用权，不自动授予模块菜单权限或资源管理权【未提交】。
