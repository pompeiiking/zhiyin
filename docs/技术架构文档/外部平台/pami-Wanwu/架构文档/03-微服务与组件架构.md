# Wanwu 微服务与组件架构

## 1. 服务全景

Wanwu 的 Go 管理面按领域拆为八个进程。BFF 提供 HTTP 接入，其余服务主要监听内部 gRPC；AgentScope、RAG 和 Python Agent 是独立运行引擎。

| 服务 | 端口 | 核心职责 | 主要依赖 | 代码入口 |
|---|---:|---|---|---|
| bff-service【混合】 | 6668 | HTTP/API 聚合、认证中间件、SSE/WS、上传、OpenAPI | 全部领域服务、MinIO、AgentScope、Agent | `cmd/bff-service/main.go` |
| iam-service【已提交】 | 8888 | 用户、组织、角色、权限和登录 | MySQL、Redis | `cmd/iam-service/main.go` |
| model-service【混合】 | 8989 | 模型配置、类型、供应商和可用模型 | MySQL、Redis、外部模型 | `cmd/model-service/main.go` |
| mcp-service【混合】 | 9898 | 内置/自定义 MCP 管理与工具描述 | MySQL、Redis、MCP Server | `cmd/mcp-service/main.go` |
| knowledge-service【混合】 | 8889 | 知识库、文档、分段、导入/删除任务 | MySQL、MinIO、Kafka、RAG 引擎 | `cmd/knowledge-service/main.go` |
| rag-service【已提交】 | 9640 | RAG 应用配置及流式问答编排 | MySQL、Redis、Knowledge、RAG 引擎 | `cmd/rag-service/main.go` |
| assistant-service【混合】 | 8890 | 智能体、Action、会话与聊天调度 | MySQL、Redis、ES、MinIO、Python Agent | `cmd/assistant-service/main.go` |
| app-service【已提交】 | 9988 | 应用空间、发布/广场等应用元数据 | MySQL、Redis | `cmd/app-service/main.go` |
| agentscope【混合】 | 6672 | 工作流保存、调试、发布和运行 | MySQL、Redis、BFF、RAG、Agent | 外部镜像 + `configs/microservice/agentscope/` |
| rag-wanwu【外部依赖】 | 8613/8681/10891/15000 | 文档处理、检索和 RAG 引擎 | MinIO、Kafka、ES、模型 | `WANWU_RAG_IMAGE` 镜像 |
| agent-wanwu【混合】 | 7258/1990–1992/15001–15003 | Agent、Action、联网、文件解析/生成 | MinIO、模型/工具 | `agent/agent_open_source/` + 镜像 |

“混合”表示服务本体已提交，但其查询、鉴权、配置或运行路径被未提交代码修改。

## 3. 典型服务内部结构

```ascii
cmd/<service>/main.go
        |
        v
config ----> server/grpc 或 server/http
                    |
                    v
                 service
                    |
          +---------+----------+
          v                    v
     client/orm             client/<remote>
          |                    |
          v                    v
       MySQL/ES          gRPC/HTTP 外部能力
```

各领域通常将传输模型置于 `proto/`，生成代码置于 `api/proto/`；数据库模型和查询位于 `internal/<service>/client/orm/`；BFF 另有 `model/request`、`model/response`、HTTP handler 和 service 聚合层。

## 4. BFF 组件

| 组件 | 职责 | 路径 |
|---|---|---|
| Router | 注册 `/v1`、`/openapi/v1`、callback 等接口 | `internal/bff-service/server/http/handler/router/` |
| Middleware | JWT、用户/组织、审计记录、资源访问 | `internal/bff-service/server/http/middleware/` |
| Handler | 参数绑定、响应转换、流式转发 | `internal/bff-service/server/http/handler/` |
| Service | 编排领域客户端和业务规则 | `internal/bff-service/service/` |
| Model | 请求/响应 DTO | `internal/bff-service/model/` |
| Client | 各内部 gRPC 服务客户端 | 各 `internal/*-service/client/client.go` |
| WebSocket | 用户连接注册与消息发送 | `internal/bff-service/pkg/websocket/` |
| Resource Access【未提交】 | 资源归属解析、成员策略与访问过滤 | `pkg/resource-access/`、`pkg/resource-scope/` |

## 5. 未提交横切改动

- 外部智能体：Assistant Proto、ORM、gRPC 服务和 BFF 请求模型新增外部配置；`pkg/external-agent/`实现多供应商 HTTP 适配。
- 资源成员授权：BFF 直接读取领域库的归属关系，策略写入 `resource_access_policies`；Model、Agent、Workflow、Knowledge、MCP 查询增加可见性过滤（Agent 资源由 Assistant service 管理）。
- 工作流授权：AgentScope 镜像通过构建期 Python AST 补丁增加过滤、执行图保护和 API Key 检查。
- 品牌/本地部署：BFF 自定义信息、Web 文案、Nginx 和 Compose 覆盖发生变化。

## 6. 边界判断

- BFF 可以聚合数据，但不应复制领域服务的核心写模型。
- 内部 gRPC 端口不应直接暴露给终端用户；Compose 默认只注释展示多数服务端口。
- AgentScope 和 RAG 镜像内部实现不可由本仓库完全证明，相关内部细节均应视为外部依赖。
- 未提交资源授权让 BFF 具有跨库读取能力，扩大了其数据权限和故障面，应作为显式架构例外管理。
