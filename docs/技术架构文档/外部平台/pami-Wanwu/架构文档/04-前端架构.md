# Wanwu 前端架构

## 1. 技术基线

前端位于 `web/`，采用 Vue 2.6、Vue Router 3、Vuex 3、Element UI、Axios 和 Vue CLI 4。工作流画布使用 AntV X6；富文本、Markdown、代码编辑分别使用 WangEditor、Markdown-It/Marked 和 Monaco；Qiankun 用于门户式集成。

## 2. 分层结构

```ascii
+----------------------------------------------------------------------------------+
| 页面层                                                                           |
| 登录 | 模型 | 知识库 | MCP | RAG | 智能体 | 工作流 | 应用空间 | 广场 | 权限       |
+------------------------------------------+---------------------------------------+
| 业务组件层                               | 未提交组件                            |
| 上传、聊天、会话、模型配置、知识选择、X6节点 | ResourceAuthorization / ExternalAgent |
+------------------------------------------+---------------------------------------+
| 应用状态与导航层                                                                 |
| Vue Router 权限过滤 | Vuex user/app/workflow | i18n | Qiankun base path          |
+----------------------------------------------------------------------------------+
| 通信与适配层                                                                     |
| Axios + JWT/x-user-id/x-org-id | SSE fetchEventSource | AbortController          |
+----------------------------------------------------------------------------------+
| 构建与交付层                                                                     |
| Vue CLI / Webpack / nginx 静态目录 / member-access 前端覆盖【未提交】             |
+----------------------------------------------------------------------------------+
```

## 3. 页面和路由

| 能力 | 主要路径 | 页面目录 |
|---|---|---|
| 登录与门户 | `/login`、`/portal/*` | `views/login`、`views/layout` |
| 模型管理 | `/modelAccess` | `views/modelAccess` |
| 知识库 | `/knowledge*` | `views/knowledge` |
| MCP | `/mcp*` | `views/mcpManagement*` |
| RAG 应用 | `/appSpace/rag`、`/rag/test` | `views/rag`、`views/appSpace` |
| 智能体 | `/appSpace/agent`、`/agent/test` | `views/agent` |
| 工作流 | `/appSpace/workflow`、`/workflow` | `views/workflow*` |
| 广场 | `/explore*` | `views/ExploreSquare` |
| 组织权限 | `/permission` | `views/permission` |

路由由 `meta.perm` 和组织权限列表过滤。前端隐藏页面只是体验控制，后端仍必须独立鉴权。

## 4. 状态管理

- `store/module/user.js`：Token、用户及组织信息。
- `store/module/app.js`：会话运行状态等应用级状态。
- `store/module/workflow.js`：工作流编辑与运行相关状态。
- `vuex-persist` 将部分状态写入浏览器存储；敏感状态的生命周期取决于退出和 401 清理逻辑。

## 5. HTTP 与 SSE

```ascii
Vue Component
   |-- request.js --> Axios interceptor --> Authorization + user/org headers --> Nginx/BFF
   `-- sseMethod.js -> fetchEventSource --> Assistant/RAG stream -------------> BFF
                               |
                               `-- AbortController：停止本地读取
```

普通响应要求业务码为 0；响应头 `new-token` 可更新 Token。SSE mixin 维护会话、增量消息、重连计数、停止状态和聊天渲染。

## 6. 工作流前端

`views/workflow/`按节点类型组织设置面板，包括开始、结束、模型、流式模型、RAG、API、代码、MCP、条件分支、意图识别、文件解析/生成和 GUI 节点。X6 提供图节点、连线、选择、滚动和小地图；前端负责编辑体验，最终运行语义由 AgentScope 决定。

## 8. 安全边界

- 前端传入的 `x-user-id`、`x-org-id` 不能作为可信身份的唯一来源，必须与 JWT 在 BFF 侧校验。
- iframe 不注入平台 Token，不共享父页面身份；CSP、X-Frame-Options 和外部登录由外部站点负责【未提交】。
- API Key 不得出现在 iframe URL、日志或前端回显中；已保存密钥以掩码返回【未提交】。
- 工作流被授权成员运行时，不能通过前端替换已保存执行图；服务端补丁负责强制该规则【未提交】。

## 9. 扩展约束

新增页面应同步路由、菜单权限、API 模块和 i18n；新增工作流节点还需更新画布节点、设置组件、序列化模型及 AgentScope 执行端，不能只增加前端组件。
