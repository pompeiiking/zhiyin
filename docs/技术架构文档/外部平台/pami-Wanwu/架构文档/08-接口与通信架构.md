# Wanwu 接口与通信架构

## 1. 通信分层

```ascii
Browser / Third-party
   | HTTPS/HTTP
   v
Nginx :8081
   |-- /aibase ----------------------> Vue 静态资源
   |-- /user/api/* -----------------> BFF HTTP
   |-- /use/model/api/* ------------> BFF HTTP
   |-- /service/api/* --------------> BFF HTTP
   |-- /workflow/api/* -------------> AgentScope HTTP
   `-- /minio/download/api/* -------> MinIO HTTP

BFF
   |-- gRPC ------------------------> IAM/Model/MCP/Knowledge/RAG/Assistant/App
   |-- HTTP ------------------------> AgentScope / Agent 辅助端点
   |-- SSE -------------------------> Browser（Assistant/RAG 增量结果）
   |-- WebSocket -------------------> Browser（用户定向消息）
   |-- OpenAPI / Callback ----------> 外部调用方或内部回调
   `-- HTTP【未提交】---------------> 外部 Agent 服务

Knowledge / RAG Engine -- Kafka ---> 文档处理事件
```

## 2. 对外 HTTP 入口

| 入口 | 用途 | 身份 |
|---|---|---|
| `/user/api/v1/*` | 控制台管理、配置、对话、上传 | Bearer JWT + 用户/组织上下文 |
| `/use/model/api/*` | 模型相关调用入口 | 按路由配置的鉴权规则 |
| `/service/api/*` | 通用服务接口 | 按接口中间件 |
| `/openapi/v1/*` | OpenAI 兼容与开放能力 | API Key/开放接口规则 |
| `/user/api/callback/*` 等 | 内部回调 | Nginx 未提交配置明确阻止外部 callback 路径【混合】 |
| `/workflow/api/*` | AgentScope 工作流 API | AgentScope 自身协议与平台身份透传 |

BFF 路由注册集中在 `internal/bff-service/server/http/handler/router/`，接口契约以路由、请求模型和 Proto 为最终依据，Swagger 用于辅助查阅。

## 3. 内部 gRPC

`proto/<domain>/*.proto` 定义服务，`api/proto/`存放生成代码。BFF 通过配置中的服务名和端口连接七个领域服务；RAG 服务另调用 Knowledge 服务。gRPC 适合结构化内部调用，但当前 Compose 网络就是主要信任边界。

| 被调服务 | 默认地址 | 主要调用者 |
|---|---|---|
| IAM | `iam-service:8888` | BFF |
| Model | `model-service:8989` | BFF |
| MCP | `mcp-service:9898` | BFF |
| Knowledge | `knowledge-service:8889` | BFF、RAG service |
| RAG | `rag-service:9640` | BFF |
| Assistant | `assistant-service:8890` | BFF |
| App | `app-service:9988` | BFF |

## 4. 流式与异步通信

| 机制 | 场景 | 特性 |
|---|---|---|
| SSE | `/assistant/stream`、`/rag/chat` | 单向增量响应；前端使用 AbortController 停止 |
| 流式 HTTP | BFF/服务与 Agent、RAG 引擎之间 | 逐块转发或封装引擎输出 |
| WebSocket | 用户连接和服务端主动消息 | BFF 内维护用户连接映射 |
| Kafka | 文档导入、解析/索引等知识任务 | 解耦 Knowledge 管理面与 RAG 引擎 |
| 内存异步任务 | 知识删除等分步操作 | `go-async` 容器；进程故障恢复能力需单独验证 |

## 5. 智能体对话通信

```ascii
Web --POST + SSE--> BFF --gRPC--> Assistant --HTTP/SSE--> Python Agent
 |                    |               |                      |
 |                    |               +--> MySQL/ES          +--> Model/MCP/Action
 |                    +<--- stream/result --------------------+
 +<------------------------- SSE events ----------------------+
```

外部智能体模式中，Assistant 改为通过 `pkg/external-agent` 发起完整响应 HTTP 请求，再复用现有 SSE 通道返回给浏览器【未提交】。这不是上游逐 Token 透传。

## 6. 错误与取消传播

- Web 请求封装将非零业务码转为 Promise 拒绝，HTTP 401 清除本地凭据并跳转登录。
- 前端普通 Axios 超时为 600 秒；SSE 由 AbortController 管理取消。
- 服务间错误由 gRPC 状态、统一错误码或 HTTP 状态转换；跨协议转换必须保留可诊断信息，但不得泄露密钥。
- 外部 Agent 默认超时 120 秒、允许 1–600 秒并限制响应体；本地取消不保证远端任务终止【未提交】。
- 成员授权 PUT 当前因请求体被 Record 中间件读取后未恢复而返回 EOF【未提交】【运行验证】。

## 7. API 兼容性规则

- 新增字段应保持旧客户端省略字段时的行为；外部智能体 `externalConfig` 采用“省略保留、null 清除”的兼容约定【未提交】。
- Proto 变更必须同步生成 `api/proto`，并同时更新 BFF 请求/响应模型。
- OpenAPI、用户 API 和 Callback 是不同信任面，不能只按 URL 复用鉴权假设。
- Nginx、BFF 路由和实际 handler 三层必须同时存在，单有 Swagger 条目不代表接口可访问。
