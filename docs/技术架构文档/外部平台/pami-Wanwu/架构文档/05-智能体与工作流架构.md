# Wanwu 智能体与工作流架构

## 1. 两类编排模型

| 模型 | 适用场景 | 核心运行单元 |
|---|---|---|
| 智能体 | 依赖 LLM 自主选择工具和知识、进行多轮对话 | Assistant service + Python Agent |
| 工作流 | 节点、连线和条件明确，强调可控与可调试 | AgentScope |

两者共用模型、知识库、MCP、文件与开放 API 能力，但保存模型、会话模型和执行引擎不同。

## 2. 智能体配置组成

```ascii
Assistant
  +-- 基本信息 / Prompt / Prologue
  +-- Chat Model
  +-- Knowledge Bases / RAG 参数
  +-- Actions
  |     +-- MCP 工具
  |     +-- OpenAPI/HTTP 工具
  |     `-- 联网检索
  +-- Conversation / History
  `-- ExternalConfig【未提交】
        +-- Dify / Agno / LangServe / LangGraph / Generic HTTP
        `-- iframe Web URL
```

## 3. 内置智能体对话时序

```ascii
User       Web         BFF          Assistant       Python Agent       Model/Tool
 | prompt  |            |               |                 |                |
 |-------->| POST/SSE   |               |                 |                |
 |         |----------->| auth + config |                 |                |
 |         |            |-------------->| load session    |                |
 |         |            |               |---------------->| ReAct/FnCall   |
 |         |            |               |                 |--------------->|
 |         |            |               |                 |<---------------|
 |         |            |<-------------- stream/result ---|                |
 |<-------- SSE events -|               | save message    |                |
```

Assistant 服务负责智能体、Action、会话和消息事实；Python Agent 负责模型推理、工具执行和流式运行。会话索引/检索使用 Elasticsearch，业务关系保存在 MySQL。

## 4. 工作流结构

工作流由图、节点配置、变量和发布状态构成。前端支持开始、结束、模型、流式模型、RAG、API、代码、MCP、条件、意图、文件解析、文件生成和 GUI 等节点。AgentScope 接收图并执行；其模型节点可调用 BFF 的 OpenAI 兼容接口，RAG 节点调用 RAG 引擎，文件节点调用 Python Agent 辅助端点。

```ascii
Start -> [Model / RAG / API / Code / MCP / File / GUI]
                         |
                         +--> Switch / Intention --> branch
                                                  |
                                                  v
                                                 End
```

## 5. 工作流调试与发布

```ascii
Developer -> Web X6 -> AgentScope :6672 -> validate/save graph
                         |
                         +-> BFF OpenAI API -> Model service -> provider
                         +-> RAG :8681 ------> knowledge index
                         +-> Agent :15002/3 -> file generate/parse
                         `-> MCP/API --------> external tool
                              |
Developer <------ streamed/debug result -----+

Published workflow -> App/Workflow API -> AgentScope -> saved graph execution
```

工作流运行记录应与定义分离；复制产生新归属，原工作流编辑和发布仍由创建者控制。

## 6. MCP 与 Action

- MCP service 管理内置和自定义 MCP 定义、连接信息与工具元数据。
- BFF 的 MCP 工具客户端负责发现或调用工具；Python Agent 的 Action 层将工具转换为模型可用函数。
- 外部工具的业务授权、限流和审计不能仅依赖 Wanwu，MCP Server 仍需自我保护。
- 工具输出属于不可信输入，进入 Prompt 前应限制大小、格式和敏感字段。

## 7. 外部智能体【未提交】

### 7.1 统一聊天模式

```ascii
Web SSE -> BFF -> Assistant -> pkg/external-agent -> External Agent HTTP
                                |                        |
                                +-- provider adapter ----+
                                +-- timeout/body limit
                                +-- response path extract
                                `-- external session mapping
```

支持 Dify Chat/Agent、Agno AgentOS、LangServe、LangGraph Stateless Run 和通用 JSON HTTP。当前实现等待上游完整 JSON，再通过既有 SSE 通道返回；不支持上游逐 Token 透传、文件上传和任意图状态。

### 7.2 外部页面模式

平台只保存并展示外部页面 URL。浏览器通过 sandboxed iframe 或新窗口访问；平台不注入用户身份，不实现 SSO 或跨页面消息协议。

## 8. 工作流成员授权【未提交】

AgentScope 镜像补丁对列表、详情、复制、执行和 API Key 路径增加成员访问判断。被授权成员可以运行已保存图，但不能保存、删除、发布、再次授权或提交替换图；执行记录继续按个人隔离。

该能力由 `configs/microservice/agentscope/org-sharing/patch.py` 在构建时修改目标镜像代码，固定适配特定上游镜像结构；上游函数变化时构建会中止，这是有意的安全失败方式。

## 9. 失败与取消边界

| 故障 | 预期影响 |
|---|---|
| 模型不可用 | 当前节点/对话失败，配置管理仍可用 |
| MCP/Action 失败 | 工具步骤失败；是否重试由 Agent/工作流语义决定 |
| AgentScope 不可用 | 工作流设计运行不可用，普通管理面部分仍可用 |
| Python Agent 不可用 | 内置智能体执行及相关辅助工具不可用 |
| 外部 Agent 超时【未提交】 | 本次回答失败；平台会话仍保留，远端任务可能继续 |
| 浏览器取消 SSE | 停止本地读取并尝试取消下游；不保证所有远端执行终止 |
