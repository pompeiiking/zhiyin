## 三、基础设施团队的本期范围（开工前必须先拍板）

第一期把 MySQL、向量库、消息队列、pami 全部按本地模拟装配，八个替换点都能跑。
因此**基础设施不阻塞本期退出条件**。这是好事，但它会带来一个很现实的排期问题：

> 不明确范围，平台的 3 个人会自然滑向下一期（换 MySQL、接向量库、接消息队列），
> 而下一期的工作不阻塞任何人。结果是"团队每天都很忙、主线一动不动"。

建议给平台侧这四件确定的事：

| # | 本期任务 | 工位 | 为什么必须现在做 |
| --- | --- | --- | --- |
| 1 | 本地环境 + 门禁 + CI 跑通 | 平台-1 | **已完成**（`platform-tt` 分支：CI 三作业 + Dockerfile + 统一部署基线；本地等价命令已复跑全绿）。原问题：依赖未装时所有人本地跑不了门禁 |
| 2 | 下一期 10 项基础设施决策 | 平台-1、平台-2 | **已完成（2026-09-16）**：结论见 [M3 启动依赖与决策登记表](评审/职引-M3启动依赖与决策登记表-v1.0.md) §四；原清单见[业务口径决策记录](评审/业务口径决策记录-v1.0.md) 第四节 |
| 3 | pami 平台对接预研 | 平台-3 | **已完成**（`platform-tt` 分支：`docs/技术架构文档/pami/pami-Wanwu/接口.md` 与《平台报错和未连通接口.md》，含 15 条已确认缺陷） |
| 4 | 本期 4 个基础设施缺口 | 平台侧**支援**（实现归数据访问负责人 / 基础设施负责人） | 见第六节。**归属以 `data/registry/ownership.json` 为准**——装配报告读的是它，本节与它不一致时错的是本节；平台侧提供环境与平台对接支援 |

**硬约束**：下一期的实现一律不 import 业务层与编排层（架构守卫会挡），且不得阻塞本期退出条件。

## A.3 逐文件清单与口径

### 1. 会话记忆服务（热身用）

类 `DefaultConversationMemoryService`，依赖 `ConversationMemoryRepository`（已实现）。

| 方法 | 做什么 |
| --- | --- |
| `get` | 按用户与任务读会话记忆 |
| `upsert` | 写入或追加摘要片段，带上当前环节与主理 |
| `list_by_user` | 列出全部任务会话记忆（左栏会话列表） |

**不要内联**：摘要生成口径（多长、包含哪些字段）属业务规则。

### 2. 资产服务（主战场）

类 `DefaultAssetService`，依赖 `AssetRepository`（已实现，11 个方法）、事件总线、影响面规则。

| 方法 | 做什么 |
| --- | --- |
| `propagate` | **核心**：影响面传播。选出受影响资产，只重算命中片段，版本 +1 |
| `save_version` | 保存一次新版本，并发出资产版本变更事件 |
| `list_versions` | 列出某类资产的历史版本 |
| `get_report` | 读诊断报告全文 |
| `list_direction_plans` | 读主攻 / 平行 / 保底三套方案 |
| `get_action_plan` | 读行动计划 |

三条口径：

1. **只重算受影响的片段，禁止整篇重新生成，版本 +1 并写差异。**
2. **"哪些字段影响哪些资产"的判定不归你写**——在 `business/policies/impact.py`，由后端-4 实现。
   你调用它的抽象基类：输入是变更的字段键加候选资产，输出是命中的资产列表。
   两边对着冻结签名并行，不互相等。
3. 业务口径第 8 条：**导师建议只作线索，不触发自动重算**。

事件：订阅画像字段更新事件，发出资产版本变更事件。事件名与载荷已在 `business/events.py` 定义，
不要散写字符串。对应端到端验收**第 5 条**：画像更新只传播到受影响资产，版本单调——这是你的核心交付。

### 3. 工作台聚合服务

类 `DefaultWorkspaceService`，依赖画像 / 资产 / 记忆 / 行为四个读侧接口。

| 方法 | 做什么 |
| --- | --- |
| `build_view` | 按五个环节聚合成工作台视图 |
| `list_sessions_summary` | 列出各任务会话的环节进度 |

**这是读写分离的读侧**：不写任何状态、不发任何事件、不做重算。允许轻微陈旧，
允许并发聚合与部分失败降级。这是最容易"顺手做多"的地方，要克制。

### 4. 功能块服务

类 `DefaultFunctionService`，依赖资产 / 行为接口与对象存储网关。

| 方法 | 做什么 |
| --- | --- |
| `get_report_full_text` | 报告全文——**只读资产版本，不重新生成** |
| `export_asset` | 导出占位，恒返回不可用 |
| `list_calendar_nodes` | 读关键节点日历 |
| `write_calendar_node` | 写节点（规划师写、教练读） |
| `list_achievements` | 读成就——**只由真实行为日志驱动解锁** |
| `list_track_events` | 读跟踪时间线（工作台第五层） |
| `get_demo_script` | 取自动演示脚本（只读演示数据） |

**不要做**登录型、浏览型徽章——这条是防"自嗨"的产品硬约束。

### 5. 影响面传播 Worker

类 `ImpactPropagationWorker`，name 为 `impact`，只有一个 `run_once`。

职责边界：**它只管"什么时候跑、跑谁"，"怎么跑"在资产服务里。** 它订阅画像字段更新事件，
调用资产服务的传播方法。同一字段可能被重复投递，因此单轮执行**必须幂等可重入**。

## A.4 装配与完成判据

每完成一个文件，做三件事：

1. 在服务装配表里接上（一行一个）；
2. 去掉实现类上的骨架标记；
3. 影响面 Worker 另外要在 worker 装配表里注册，否则不会被生命周期启停。

完成信号（不需要另做汇报）：

- 装配检查里对应项从"待实现"变为"已装配"；
- 端到端验收第 5 条从跳过变为执行并通过；
- 合并前门禁全绿。
