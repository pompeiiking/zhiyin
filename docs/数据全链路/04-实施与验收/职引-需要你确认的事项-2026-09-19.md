## 二、需要你选改法的两项（技术决策）

### 1. D12 · 线上检索内容仍是演示卡（**新发现，优先**）

- **事实**：向量库 0 行、权威文档表 0 行、本地知识库只有 6 张**标注 DEMO** 的卡片；而容器内真实关键词通道正是它，且相位门禁照常判它 `wired`、`/healthz` 显示 `ok`。
- **为什么要你定**：三条改法都会改变运行行为——A 会让当前"phase 1/2/3 全绿"变成不满足（甚至起不来），B 要动引用核对与报告呈现，C 等于默认接受演示内容被引用。
- **我的建议**：**先做"如实上报"**（让装配报告与 `/healthz` 显式标出"检索内容来自演示库"，不改变能否启动），**再给证据打演示标记并让引用核对拒绝演示证据**；不建议只做 C，也不建议一上来就硬失败。
- **依据与代价**：[待决问题 D12](职引-待决问题与改法选项-v1.0.md) · 证据见[修改日志 §20](../00-索引与变更/职引-数据全链路修改日志.md)

### 2. D11 · 检索证据 id 口径不一致（`namespace:id` vs 裸 id）

- **事实**：评测集期望一律 `namespace:id`，而本地关键词通道返回**裸 id**；两者不匹配使评测期望覆盖率为 0，且同一篇文档在关键词/向量两条通道里 `evidence_id` 不同，**RRF 去重会把一篇当两篇**。
- **我的建议**：改法 **A**（统一为 `namespace:id`）——唯一键必须含 namespace；但要与引用核对、RRF 去重、评测集三处一起改并跑回归。
- **要你确认**：是否同意改法 A 并接受它属于检索契约调整。
- **依据**：[待决问题 D11](职引-待决问题与改法选项-v1.0.md)

## 三、需要你出人/出权限的三项（我做完即解除阻塞）

### 3. 平台侧：`callback_url` 一行配置（**卡住整条 RAG 链路**）

- **现象**：知识库已建成、22 份文档已导入，但**解析全部失败**（`know_doc_parsing_service_error`）。
- **根因**：平台 `bff-service` 的 `callback_url` 指向 `http://172.17.0.1:6668`（Docker 宿主网关），RAG 容器在 compose 网络内**连不上**。同网络实测：该地址 `Connection refused`，改指 `bff-service:6668` 返回 `200`。
- **为什么我不改**：平台是 vendored 第三方工程（带 `UPSTREAM.md` / `.zhiyin-vendor.json`），《AGENTS.md》§10 明确"职引侧不得自行修改外部平台契约"。
- **需要你**：让平台负责人把该配置改为 compose 服务名（或明确授权我改这一行）。
- **解除后我会做**：重跑解析 → 发布 RAG 应用 → 建 Key → **把 Key 写进 `deploy/.env`（已 gitignore，不进仓库/日志/聊天）** → 用真实问题验证 PAMI 检索 → 重跑基准评测 → 出新的质量数字供你冻结门槛。

### 4. 内容侧：16 张理论卡定稿 + 来源台账

- **现状**：16 张理论卡只有 `name/school/summary/product_usage`，**缺方法步骤 / 适用边界 / 示例 / 来源**；`sources.json` 4 条来源台账需扩写。
- **我可以做**：按现有字段起草补全稿。
- **需要你**：指定领域负责人**定稿**（属职业咨询专业内容，我不能自批），并确认来源台账可发布。
- **为什么必须有**：现在的 22 份文档里理论卡那 16 份就是摘要级内容；不补全，即使 RAG 通了，报告引用的也只是摘要。

### 5. 合规侧：招聘来源审核（放行前置）

- **现状**：`sources.json` 里 4 条来源已含 `allowed` / `access_basis` / `retention` / `removal_method`，但**条款、robots、字段范围、抓取频率、保存期限五项审核未做**。
- **需要你或合规**：逐项确认或授权。
- **我的边界**：**不碰招聘来源抓取**；审核未完成前，`src-job-board-pending` 保持 `allowed=false` / `pending_status`。
