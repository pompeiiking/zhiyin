## 零、本轮与 v1.1 的关系

v1.1 已经论证过"分层正确、契约归属唯一、约束已变成可执行断言"，**那部分结论本轮不复评**。
本轮只做两件事：

1. 沿用 v1.1 自己的修法（"先找出口、再找守卫"），把**最后 5 处同类洞**补上（§四）；
2. 把"改一处要动几个文件"再量化一次，作为团队排期与分工的输入（§五）。

v1.1 的 §三（架构合理性复核）与 §6.1（四项业务口径待定稿）**继续有效**，
本文 §三 只写增量与"需要保持克制"的部分。

## 一、结论摘要

| 维度 | 判定 | 依据 |
| --- | --- | --- |
| 分层与依赖方向 | **高（保留）** | AST 逐文件校验；内核零依赖；本轮新增"能力位重名 / 拼写 / 字段脱节"三条守卫 |
| 契约归属 | **高** | 四类契约各有唯一归属；本轮把"同一个值在两处手抄"降到只剩一处手抄（错误码），并用编译期 + 断言双重对齐 |
| 外壳完整度 | **高** | 43 个能力位：wired 27 / skeleton 1 / not_wired 15，全部有落位与归属；M3 的替换点补上空抽屉 |
| 跨语言口径 | **中高 → 高** | 错误码、页面锚点、接口清单、组件落位表全部有守卫；前端类型由入库契约快照生成，不再需要"先起后端" |
| 可机械守卫程度 | **高** | 越层 / 落位缺失 / 骨架冒充完成 / 动态资源引用 / Mapper 绕开 / 契约漂移 / 跨语言漂移 / 装配清单漂移 均有断言 |
| 联调并行度 | **中（已定位）** | Facade 未实现时业务接口全 503，前端"能不能开工"取决于团队对 mock 方式的选择（§六 决策 2） |
| 剩余风险 | **中（已定位、已分配）** | 4 项业务口径未定稿；3 项决策待团队拍板；后端跑真存储前仍是内存实现 |

一句话：**这份骨架已经可以交给 3–5 个人并行开工，且"改一处要动几个文件"是已知数**；
本轮清掉的是那类**不会报错、只会静默空值或静默 404** 的缺口——它们比缺文件贵得多。

## 三、架构合理性复核（增量）

### 3.1 这套结构"合理"的机制层理由

判断架构合理性不看风格，看**每条约束有没有机械落点**。逐条核对如下：

| # | 设计 | 为什么合理（机制） | 守卫 |
| --- | --- | --- | --- |
| R1 | 四层 + BFF + 装配层，单向依赖 | 每层职责单一；`infrastructure → data_sdk` 是依赖倒置，最难画对的一跳方向正确 | `test_no_cross_layer_or_reverse_dependency` |
| R2 | 内核独立成包且零依赖，且有**准入规则**（只放数据形状与无方法体的最小契约） | "领域模型归谁"不再有歧义；行为一进内核就会带依赖与副作用，所以内核用 AST 守卫**拒绝带方法体的类** | `test_kernel_has_no_dependencies`、`test_kernel_holds_only_shapes_and_contracts` |
| R3 | 四类契约各有唯一归属 | 一类契约一个家，"我应该在哪找它"变成可回答问题 | `test_no_duplicate_contract_definitions` |
| R4 | 装配可观测（wired / skeleton / not_wired + 归属） | "文件存在 ≠ 能力具备"被机械保证；缺口带负责人，红灯有行动含义 | `describe_assembly` + `test_skeleton_is_reported_not_hidden` |
| R5 | 动态资源不进代码（含**规则参数**） | 文案 / 任务入口 / 智能体 / 理论卡 / 产出契约 / 开关 / 阈值都能不改代码生效 | `test_registry_cross_references_are_closed`、`test_dynamic_resource_files_exist` |
| R6 | 分级门禁（M1–M4） | 二值的 `healthy` 只有一个含义（全绿），会让本期长期"未达标"而失去信号；分级后 CI 能精确卡口 | `--check --phase=N` + `test_gates_reference_known_ports` |

### 3.2 需要保持克制的地方（更新）

| # | 设计 | 风险 | 处置（本轮更新） |
| --- | --- | --- | --- |
| C1 | 编排层"通用、零业务语义"（为 pami 平台将来复用） | 第一期只有职引一个消费者，为未来预付抽象成本 | **继续冻结**：现有六原语保留，不再新增原语 |
| C2 | 语义契约（orchestration）与传输契约（data_sdk）双份 | 同义概念可能分叉 | 已定案：传输契约只保留最小能力；本轮在 `kafka/` 抽屉里把这条口径写成明文（"不建第二套事件抽象"） |
| C3 | CQRS-lite 只到接口层 | 读侧实现时容易又混在一起 | 口径已写进 `ports/workspace.py` 与 `ports/registry.py`：读侧**不写状态、不发事件** |
| C4 | 加一个能力位要动 4–5 个文件 | 并行冲突点 | **保持现状**：把"现状可见"看得比"改一处"重要；漂移由 `test_assembly.py` 挡住 |
| C5 | **跨语言口径只能手抄一份**（错误码表在 `client.ts`） | 手抄就会漂移 | **本轮新增**：抄写处由编译期联合类型（`satisfies`）+ 断言双重对齐；**不再新增第二份手抄表**，新常量一律先由后端 OpenAPI 生成 |

## 四、本轮修掉的 5 个结构洞

判定标准与 v1.1 相同：**改一处要动几个文件、会不会牵动别人**，以及"症状是否静默"。

| # | 洞 | 现象（修之前的真实状态） | 代价 | 处置 |
| --- | --- | --- | --- | --- |
| H7 | **`trace_id` 有契约、无生产者** | `ApiResponse.trace_id` 与前端 `ApiError.traceId` 都在用这个字段，M4 门禁也写着"trace_id 端到端贯通"，但全仓没有任何地方生成它——恒为空字符串 | 联调期拿到 503 却无法把"前端看到的错"与"后端日志"对上；排查成本随并发升高 | 新增 `zhiyin_api/context.py`：纯 ASGI 中间件生成/沿用 `X-Trace-Id` → 写 `contextvars` → 回写响应头；信封 `trace_id` 由 `current_trace_id()` 兜底。守卫断言**唯一生产者**（含"其它层不得生成"与"ContextVar 只能定义一处"） |
| H8 | **前端类型来源不可用** | `npm run gen:api` 要求后端正在本机跑；CI 无法检查类型漂移；`types.ts` 是 `Record<string, never>` 空占位——**看起来有类型，其实什么字段都接受** | 前端被后端进程绑住；字段漂移只能在联调时暴露 | 新增接口契约快照链路：`contracts/openapi.json`（入库）+ `scripts/export_openapi.py` + `tests/test_api_contract.py` + `npm run gen:api/check:api` + CI 步骤；`types.ts` 换成真生成物，手写别名集中到 `src/api/schema.ts` |
| H9 | **跨语言口径无守卫** | 错误码、`PAGE_ANCHORS`、接口 url 清单、22 个组件落位表，四处都是"两边各写一遍 + 注释说必须一致" | 错误码错一位 → UI 走进通用分支；url 漂移 → 404 而 OpenAPI 看着有这条路由；组件表漂移 → 新人照表找文件扑空 | 新增 `tests/test_frontend_alignment.py`（错误码双向比对、锚点/`require_login` 逐条对齐、菜单指向真实路由、url ↔ 后端路径双向、组件落位表 ↔ 真实文件）；`client.ts` 加 `satisfies` 编译期守卫 |
| H10 | **替换点没有落点** | 八个替换点里 Redis / pgvector / Kafka / MinIO / 真实模型只有 `local/` 一个家；实现时只能塞进 `local/`（名字与内容不符）或临时新建目录（命名各写一套） | "实现放哪"这个决定被推迟到实现当天，必然与别人撞 | 补 `redis/` / `pgvector/` / `kafka/` / `llm/` / `minio/` 五个空抽屉（各自带 Port 清单、开工前置条件、"不要写回 local/"），同步 `pyproject.toml`；抽屉守卫从 5 个目录扩到 10 个 |
| H11 | **装配守卫有盲区** | ① 能力位重名没有守卫；② `MINIMUM_VIABLE` 拼错时启动会永远报"缺少必需部件"；③ 能力位名与 `Container` 字段名脱节时报告会一直说谎（永远 not_wired）；④ 测试之间共享全局装配（谁踩谁修） | 这三类都不会报错，只会让报告与门禁"看起来正常" | `tests/test_assembly.py` 增 3 条守卫（含 4 个例外的登记表 `PORT_NOT_A_CONTAINER_FIELD`）；新增 `tests/conftest.py` 自动还原 `configure_runtime` / `configure_facade` 两个全局注入点 |

> H7 与 H11③ 是同一类：**契约/清单里有的东西，链路上没人负责**。它们的共同特征是
> **不报错**——这正是 v1.1 那句话的含义：静默回落比报错贵得多。

### 5.2 剩余并行冲突点（已知，可接受）

| 文件 | 为什么会被多人同时改 | 缓解 |
| --- | --- | --- |
| `container/ports.py` | 每加一个能力位都要加一行 | 冲突是行级追加；以它为准解决冲突 |
| `business/services/__init__.py` | 落位表 + 全部 import 的汇合点 | 保持（它是"一眼看全 10 个服务"的唯一地方），表格一致性由守卫保证 |
| `api/dto/mappers.py` | 所有字段口径的唯一处 | 一个函数一个字段组，函数级并行；签名已冻结 |
| `data/registry/ownership.json` | 归属清单 | 行级追加 |
| `contracts/openapi.json` + `src/api/types.ts` | **生成物**，任何 DTO 变更都会动它们 | 约定：只由脚本生成、冲突时**重新生成**而不是手工合并（这是本轮新增的协作规则） |

### 5.3 本轮降低的成本（前 → 后）

| 场景 | 之前 | 之后 |
| --- | --- | --- |
| 前端拿类型 | 需要后端在本机跑 | `npm run gen:api`（读入库快照，不依赖进程） |
| 后端改字段 | 靠人记得重新生成前端类型 | CI 的 `npm run check:api` 直接失败 |
| 排查一次 503 | trace_id 恒空，只能按时间猜 | 响应头与信封同一个 id，日志可串 |
| Redis / 向量库实现落地 | 得先问"放哪个目录" | 抽屉已就位，开工前条件写在目录里 |
| 测试互相污染 | 谁踩到谁自己调 `reset_runtime()` | 自动夹具统一还原 |
| 报告与门禁的可信度 | 能力位拼错/重名时会安静地报错状态 | 三条新增守卫挡住 |

## 六、仍然存在的耦合点与待决策（需要团队/产品拍板）

这三项**不是技术缺口，是决策缺口**。技术上每项都已定位到落点，但"该不该做、做成什么形状"
会影响接口与产品口径，因此本轮**刻意不建空契约**（理由同 `zhiyin_kernel/dynamic_content.py`
里已写明的口径：没有消费者就先不建形状，避免"看起来能配、实际没人读"）。

| # | 待决策 | 现状 | 两个选项与代价 | 建议 |
| --- | --- | --- | --- | --- |
| D1 | **埋点上报通道** | PRD §十一 有 23 个事件名，内核 `BehaviorEventType` 有 9 个取值，两者部分重叠；《前端设计》§8 把其中 14 个的触发点放在前端。目前前端只有注释，没有上报函数，后端也没有接收端点 | A. 前端上报：加 `POST /app/track` + DTO + Facade + 前端 `src/analytics/` + 事件目录动态资源；B. 后端派生：把"首页点卡 → 就是 enter_task"这类事件在 BFF 内部记，前端零上报，但纯浏览型事件（`conv_disclosure_open`）拿不到 | 先定**事件归属表**（哪些事件由后端派生、哪些必须前端上报），再决定接口——顺序反了会返工 |
| D2 | **前端并行联调方式** | Facade 未实现时所有 `/app/*` 返回 503，前端只能对着类型与文档写，不能看到真实渲染 | A. boot 侧 mock Facade（`ZHIYIN_MOCK=1` 开关 + 自报 `skeleton`，数据来自动态资源）；B. 前端 MSW / 静态 JSON 夹具；C. 等 Facade 实现 | 若前端要"今天就开工"，A 或 B 二选一：A 能顺带成为 FR-BLOCK-005 自动演示的数据源，B 对后端零侵入 |
| D3 | **SSE / WS 的 api 落点** | 八替换点里有 SSE；`Notifier` 传输契约已有（`gateways.messaging`），但**推送端点**在 api 层还没有落位（没有流式 controller） | A. 现在建 `controllers/stream_controller.py` 骨架；B. 等 PRD 明确"哪些内容要推、断线重连与幂等口径"再建 | 与 D1 一起定：两者都涉及"前端主动取 / 后端主动推"的边界 |

## 九、一句话结论
