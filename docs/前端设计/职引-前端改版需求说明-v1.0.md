## 〇、一页速览（需求确认单）

### 0.1 先确认：我理解的需求（请逐条核对，任一条不符请先纠正再开工）

1. 你要的不是「局部调色」，而是三个页面的**结构级重做**：首页换叙事与展示方式，对话页换版式并锁死滚动，工作台换信息架构。
2. 你要的核心不是单纯的「好看」，而是**同时达标三件事**：视觉质感、动效/技术含量、信息设计。
3. 你要把已有的核心设计资产（三轴、五环节闭环、智能体能力池、活资产与长期跟踪）**从文档里的概念，变成用户一眼看得见、点得开、看得懂的界面**。
4. 你要把一次性交付变成持续经营：**推广（让更多人进来）+ 推送（让人持续回来）**。
5. 明确不要：英文装饰小字、空壳占位块、纯文字堆叠的「说明书式」页面、只有边框没有层次的卡片墙。

## 一、背景、目标与范围

### 1.1 现状问题（需求方原话 → 可验收的问题描述）

#### 首页

| 原话 | 问题本质 | 现状证据 |
| --- | --- | --- |
| 「不要有英文小字」 | 界面散落多处英文/中英混排的装饰性小字，不承载信息，削弱专业感 | 首屏「ZHIYIN · AI CAREER COACH」、区块标签「CAREER WORKBENCHES」「ROLE PLAY · 身份演示」「平台输出能力 / WHAT YOU GET」、卡片代号「CAMPUS / POSTGRAD / CIVIL SERVICE / EARLY CAREER」 |
| 「下部分的展示板需要有内容，而不是简单的一些小块」 | 页面下半部分没有「产品实感」，用户看不到产出物长什么样 | 「3 步从对话到行动」是三张纯文字卡；「职业工作台矩阵」4 张卡中 3 张是「即将开放」空壳 |
| 「背景太素没有动态效果」 | 首屏缺乏技术感与记忆点 | 背景为纯米白底 + 局部静态渐变，无动态层 |
| 「没有现代前端设计的高级特性，没有技术性」 | 与「AI + 咨询方法论」的产品定位不匹配 | 全站仅一处滚动进入动效；无数据可视化、无微交互体系、无共享元素过渡 |
| 「整体的结构需要优化」 | 首屏信息密度过高、缺少视觉主轴 | 首屏连续堆叠：标题 + 副文案 + 三按钮 + 说明行 + 对话预览卡 + 四组数字 + 三张步骤卡 + 四张工作台卡 + 三张身份卡 |

#### 核心对话页

| 原话 | 问题本质 | 现状证据 |
| --- | --- | --- |
| 「整个页面不能上下滑动，只能对话框和右边框内部滑动」 | 整页滚动 + 内部容器滚动形成「双层滚动」，顶栏与进度条会被滚走，用户丢失上下文 | 页面自身可滚动；对话流另有固定高度内部滚动 |
| 「版式需要优化，整体好丑，没有设计感」 | 顶部阶段条、对话卡、右侧画像卡三方各自为政，缺少统一框架 | 阶段条浮在页面顶部，与下方两栏不在同一网格里 |
| 「有边框的详细属性应该有层次感」 | 卡片、分组、字段、标签几乎都用同一档描边与底色，层级扁平 | 右栏画像卡为「一张卡 + 若干同规格分组 + 同规格字段」 |
| 「要放入我们新的心智模型，体现核心设计和三轴设计」 | 前台只体现了轴 B 的一小段；轴 C 只在文字里出现；②-⑤ 环节没有对应容器 | 右栏只有「个人画像」（对应①采集）一整块 |

#### 智能工作台（第三页）

| 原话 | 问题本质 | 现状证据 |
| --- | --- | --- |
| 「因为要承担很多信息展示，应该做成多级的」 | 一屏平铺全部内容，扫视成本高、重点不突出 | 同屏并列：5 张智能体卡 + 报告摘要 + 长期跟踪时间线 + 成长成就 + 关键节点日历 + 4 个操作按钮 |
| 「所有内容尤其是分析流程和理论模型都应该能通过各种二级菜单打开并分析」 | 结论平铺在前面，推理过程与理论依据被藏成标签，点不开、看不透 | 理论只以气泡上的小标签形式出现，无展开、无内容 |
| 「具备现代前端的交互性，气泡等等」 | 教练消息是静态时间线节点，不是可交互消息 | 时间线节点为静态文本块 |
| 「要根据我们的长期跟踪的三轴设计思想重新分析功能展示和使用逻辑」 | 工作台按「卡片类型」排布，而不是按三轴与五环节排布 | 智能体矩阵、报告、时间线、成就、日历并列，没有主轴 |

#### 推广与推送

现状完全没有：仓库里只有一句「节点提醒接入真实推送通道」的后续迭代备注，无消息中心、无分享、无邀请、无触达规则。

### 1.2 本次目标（验收导向）

| 目标 | 判定标准（陌生人视角） |
| --- | --- |
| 专业感 | 打开首页 5 秒内能说出「这是一个有理论依据的职业规划 AI」 |
| 技术感 | 首页与工作台各出现至少 2 处数据/流程可视化或高级交互，且都承载真实信息 |
| 结构清晰 | 三页都做到「一层一屏、由轻到复杂」；对话页在桌面端零整页滚动 |
| 心智可见 | 三轴在界面中可见、可点开：轴 B 是主结构，轴 C 显示「谁在帮我 + 依据」，轴 A 显示「系统判断你处在哪个阶段」且用户可纠正 |
| 可持续经营 | 用户有明确推广入口；有消息中心与推送，且打扰可控 |

### 1.3 范围、边界与变更管理

- **在范围内**：三个页面的新版版式、视觉、动效与交互；推广与推送的能力需求；连带页面（登录、完整报告、导师视图）的一致性改造；验收清单与接口依赖清单。
- **不在范围内**：业务语义与算法（三轴定义、五环节理论链、匹配度算法、编排规则）、数据模型、身份权限规则的变更。若实现新界面需要新数据，按 §9.3 提出。
- **需求编号规则**：本文件新增 `HOME-xxx`（首页）/ `CONV-xxx`（对话页）/ `WB-xxx`（工作台）/ `GRW-xxx`（推广）/ `PSH-xxx`（推送）/ `OTH-xxx`（连带与其他）；每节标注与 PRD 功能需求编号的追溯关系。
- **完成定义**：一条需求只有同时满足「本文档的验收标准」+「PRD 对应 FR 的业务口径」+「CI 门禁不红」才算完成。

## 二、统一设计原则（三页共同遵守）

### 2.1 新的心智模型（本次改版的「灵魂」）

> **一句话：始终知道「谁在帮我、凭什么、我下一步做什么」——而我的每一步都在长成一份活的资产。**

这六条心智必须能在界面上被找到，否则视为未实现：

| 心智 | 用户心里的话 | 界面必须存在的东西 | 主要落点 |
| --- | --- | --- | --- |
| 谁在帮我 | 「现在是职业顾问在跟我说话」 | 主理徽章（角色色 + 名称 + 当前状态） | 对话页顶栏与气泡、工作台能力区 |
| 凭什么 | 「他为什么这么说」 | 可点开的理论标签 → 理论模型卡 | 对话页气泡与右栏、工作台二级菜单 |
| 下一步做什么 | 「我现在到底该干嘛」 | 行为引导区：追问 / 选项 / 小任务 / 提醒 四选一 | 对话页底部、工作台「今日行动」 |
| 我在哪一环 | 「我走到第几步了」 | 五环节闭环进度（①-⑤，含再入环） | 对话页右栏、工作台主结构 |
| 我的资产在长 | 「我的画像/报告/计划一直在更新」 | 活资产状态：版本 + 更新时间 + 变化点 | 工作台分层与版本对比 |
| 全程有证据 | 「结论不是拍脑袋」 | 证据来源（岗位要求 / 知识库 / 行为日志）+ 时间戳 | 二级明细层 |

### 2.2 三轴在界面上的投影（硬性要求）

| 轴 | 性质 | 界面投影（必须实现） | 明确不允许 |
| --- | --- | --- | --- |
| 轴 A · 用户职业发展进程 | **隐性**，后台推断 | 工作台顶部「阶段定位条」：显示系统判断的阶段、判断依据、以及一个「不是这样，我来纠正」入口 | 不允许要求用户先选阶段；不允许把阶段做成导航层级 |
| 轴 B · 服务微循环 | **显性**，主结构 | 五环节闭环：①采集建模 → ②诊断匹配 → ③决策 → ④行动 → ⑤复盘校准（含回环）；对话页右栏管线卡与工作台主骨架 | 不允许出现与五环节并行的第二套步骤体系（例如旧的「对话建档 / 15 维解析 / 方向方案 / 行动计划」四段式保留为并列导航） |
| 轴 C · 能力与编排 | 引擎，后台 | 「谁在帮我」区域：主理 + 协理 + 信息侦查员、当前动作、交接历史 | 不允许不告知就换主理；不允许把智能体做成「各自一个页面」的并列功能入口 |

### 2.3 信息分层与渐进披露（三页共同）

统一分为四层，从上到下「由轻到复杂」：

| 层 | 内容 | 呈现方式 |
| --- | --- | --- |
| L0 呼吸层 | 「我现在在哪 + 下一步做什么」 | 一屏一个视觉焦点，始终可见 |
| L1 概览层 | 关键状态与入口（不超过 3 个并列区块） | 卡片 / 状态条 |
| L2 明细层 | 环节明细、维度明细、计划明细 | 抽屉 / 二级面板 / 二级页 |
| L3 依据层 | 理论模型、证据来源、版本历史、行为日志 | 二级菜单打开，默认收起 |

**规则**：L2/L3 一律「点开才出现」，不默认展开；任何可点开元素必须有进入线索（箭头 / 下划线 / hover 态 / 「查看 →」文案）与「关闭返回原位」；展开后必须能一眼看出它与上一层的从属关系。

**反例（出现即不合格）**：一屏 12 张卡平铺、所有文本默认展开、点开没有位置感、二级内容回到列表后丢失滚动位置。

### 2.4 视觉与文案原则

1. **中文优先**：界面不得出现纯装饰性的英文小字。仅三处允许出现英文：品牌名（logo 与分享物料）、国际通用理论缩写（RIASEC / CASVE / SMART / CD 等，首次出现必须带中文释义）、必要的技术状态词（AI）。
2. **层次优先于边框**：用底色深浅、间距、字重、圆角区分层级，不靠「到处加 1px 描边」。
3. **一屏一个焦点**：任意一屏只能有一个最强视觉元素。
4. **品牌色沿用现有令牌语义**：蓝＝主行动、绿＝完成/成长、琥珀＝注意/缓冲、红＝风险（弱化使用）、紫＝智能体/角色。若要升级视觉风格，须先提交视觉方案再落地。
5. **文案基调**：专业但不端着；教练语气（鼓励 + 一个最小行动）；禁止焦虑营销、夸大承诺、施压式措辞。

### 2.5 动效与技术基线（「要有技术性」的判定标准）

| 特性 | 用在哪 | 判定标准 |
| --- | --- | --- |
| 背景动态层 | 首页首屏、工作台头部 | 存在缓慢循环动效（单循环 ≥ 20 秒），不闪烁；叠加文字对比度不受影响 |
| 滚动叙事 | 首页 | 滚动过程中至少 3 个区块出现分层进入、视差或编号推进效果 |
| 数据可视化 | 首页展示台、对话页右栏、工作台 | 至少包含：15 维热力/雷达图、闭环进度环或流程条、时间线、差距条；图形有入场动画且可 hover 出详情 |
| 微交互 | 全局 | 按钮/卡片/标签具备 hover、focus、active 三态；点击有即时反馈，不依赖 toast 兜底 |
| 共享元素过渡 | 工作台卡片 → 二级抽屉 | 卡片展开为详情时有连续的位置/尺寸过渡，而不是直接弹窗 |
| 流式输出 | 对话页 | AI 回复分段/逐字出现，并显示当前动作（如「正在读你的画像」） |
| 骨架与空态 | 全部 | 异步区域使用骨架屏，不使用「加载中…」纯文本 |
| 性能预算 | 全局 | 首页首屏最大内容绘制 ≤ 2.5 秒（4G / 中端机）；动效保持 60fps；图表与动效按需加载 |
| 无障碍降级 | 全局 | 尊重系统「减少动态效果」设置；键盘可达；文字对比度达 WCAG AA |
| 明确禁止 | 全局 | 为动效而动的装饰动画、进入即自动播放的音视频、超过两层的玻璃拟态堆叠 |

### 2.6 视口与滚动总规则

1. 应用型页面（对话页、工作台）采用**整页锁定 + 分区滚动**：页面本身不产生纵向滚动条。
2. 可滚动容器必须显式声明（白名单见各页章节），每个容器有独立滚动条样式，并在切换页面时保留滚动位置。
3. 顶部导航与底部行为引导固定，中间正文区独立滚动。
4. 移动端（≤ 900px）允许整页滚动，但必须按 §4.7 与 §5.8 的重排规则降级。

## 三、页面一：首页改版（HOME）

**对应 PRD**：FR-HOME-001 ~ FR-HOME-006（任务式首页、任务路由、兜底开聊、信任建立、脱敏示例、身份感知）。

### 3.1 改版目标

从「功能清单式落地页」改为**「一句话价值主张 + 产品实感展示 + 可信方法论」**三段式叙事；让游客在不登录的情况下就能看到产品会产出什么。

### 3.2 新版页面结构

### 4.4 右栏「层次化属性」规范（CONV-003，对应用户提出的「有边框的详细属性应该有层次感」）

适用范围：**所有"用卡片承载详细属性"的地方**——对话页右栏的画像字段、管线卡明细、工作台的节点卡明细。统一定义为三层，禁止出现第四层：

| 层级 | 名称 | 视觉规格 | 允许的边框 |
| --- | --- | --- | --- |
| L1 | 环节卡 / 容器卡 | 圆角最大、白底、投影最轻；**默认只有 1px 浅描边或干脆无描边** | 1 档 |
| L2 | 分组 | 圆角中等、浅灰底、**无描边**；组标题小字灰色 | 0 档 |
| L3 | 属性行 | 无边框、无底色；行间用极浅分隔线；左字段名（灰）· 中值（深）· 右状态徽记 | 0 档 |

**强化规则**：

1. 同一张卡内，描边只允许出现在 L1；L2/L3 一律用底色与间距区分。
2. 属性行展开时，用**左侧竖线 + 12px 缩进**表达从属关系，不使用嵌套边框。
3. 状态用徽记表达：已沉淀＝绿色圆点、待采集＝灰色圆点、低置信度＝琥珀色、风险＝红色（弱化使用）。
4. 同一屏内描边颜色不超过 2 种。
5. 当前激活的环节卡：左侧 3px 强调色条 + 浅色底 + 轻微上浮，是整栏唯一的强视觉。

**验收**：任取一张右栏卡截图，1 秒内能分辨出「容器 / 分组 / 字段」三层，且能指出每个字段的名称、值、状态。

### 4.5 右栏管线卡：把三轴放进界面（CONV-004）

1. **轴 B 是骨架**：①-⑤ 每环节一张卡，横向或纵向形成一条可见的闭环；闭环末尾有「再入环」回环指示。
2. **每张卡三态**（同一时刻最多展开一层）：
   - 态一「当前产出」：本期产出的最短结论 + 更新时间 + 「查看明细 →」；
   - 态二「理论模型」：本环节用到的模型名（可点开进入理论模型卡）；
   - 态三「评价状态」：字段覆盖度/置信度/完成度/风险提示。
3. **空环节也要有内容**：未进入的环节显示「待进入」+ 一句话说明这一步会做什么，不允许空白。
4. **轴 C 可见**：每张卡标注当前主理（角色色 + 名称），并在卡片内保留「交接记录」入口。
5. **当前环节高亮**：使用呼吸光效但幅度克制（不闪烁）；用户点其他环节可查看该环节历史（只读，不改变当前进度）。

## 五、页面三：智能工作台改版（WB）

> 说明：本节的「第三页」指用户口中「要承担很多信息展示」的那个页面，即智能工作台（长期跟踪与资产总控页，页面锚点为 `#screen-wb`）。完整报告页（`#screen-report`）作为二级只读视图，一致性改造见 §8。

### 5.1 改版目标

### 5.2 三级信息架构

| 层 | 内容 | 呈现 |
| --- | --- | --- |
| L1 总览层 | ① 三轴状态条（阶段定位 + 闭环进度 + 谁在帮我）；② 今日/本周该做什么（教练建议 1–3 条气泡）；③ 资产健康度（画像覆盖度、报告新鲜度、计划完成度） | 首屏，不超过 3 个并列区块 |
| L2 环节层 | 五环节区域卡：① 采集建模（画像状态）② 诊断匹配（诊断与报告版本）③ 决策（方案与历史版本）④ 行动（计划与日历）⑤ 复盘校准（跟踪、提醒与预警）；次级位置挂成就与功能块 | 一屏内可见，可折叠 |
| L3 明细层 | 每张环节卡的二级菜单：查看分析流程 / 查看理论依据 / 查看历史版本 / 查看证据 / 查看明细 | 抽屉或二级页 |

**二级菜单规范（统一命名，不得各写各的）**：

1. 「查看分析流程 →」：打开该环节的推理链可视化（§5.4）；
2. 「查看理论依据 →」：打开该环节用到的理论模型卡（§5.5）；
3. 「查看历史版本 →」：版本对比与变化原因（变化点 + 触发来源）；
4. 「查看证据 →」：结论引用的画像字段、岗位要求、行为日志、时间戳；
5. 「查看明细 →」：该环节的完整产出内容。

### 5.3 按长期跟踪的三轴思想重排功能展示与使用逻辑（WB-004）

现状按「卡片类型」并列，本次改为**按轴组织**：

| 轴 | 在页面上的位置 | 承担什么 | 明确改掉什么 |
| --- | --- | --- | --- |
| 轴 A（隐性） | 页面最顶部阶段定位条 | 显示「系统判断你处在：冲刺行动期」+ 判断依据 + 纠正入口 | 改掉「用户不知道系统怎么看他」的黑箱感 |
| 轴 B（显性） | 页面主骨架（L2 五环节） | 资产按环节归位，形成闭环 | 改掉「智能体矩阵 / 报告 / 时间线 / 成就 / 日历」并列的平铺结构 |
| 轴 C（引擎） | 总览层的「谁在帮我」区 | 主理 / 协理 / 信息侦查员 + 最近动作 + 交接记录 | 改掉「五个智能体并列成功能入口」的写法；智能体是能力池，不是五个独立页面 |

> **重要口径修正**：现原型中的「子智能体独立对话页」与 PRD「智能体＝能力池、不各自独占页面」相冲突。本次统一改为：点击任一智能体 → 打开「能力详情抽屉」（它能做什么、最近做了什么、依据什么、调用了哪些数据），**不新建并列的独立对话页**。

### 5.4 分析流程可视化（WB-002，本次重点）

**形态**：一条可交互的流程可视化，节点为「五环节 × 当前主理 × 理论链 × 产出 × 推动的行为」。

点击任一节点，展开该节点的**四元组**（PRD §2.4 判据）：

| 四元组 | 内容 |
| --- | --- |
| 用户此刻的行为/卡点 | 你当时说了什么、做了什么（引用真实输入或行为日志） |
| 用哪套理论解读 | 理论模型名 + 一句话说明它怎么解读你 |
| 推理产出什么 | 该环节产出的具体内容（结论、差距、方案、计划） |
| 推动你哪一个下一步行为 | 系统希望你做的那个动作，以及你是否做了 |

**附加要求**：支持时间轴视图，按时间回看每一轮分析（输入 → 理论 → 产出 → 行为结果），形成「推理历史」。

**验收**：从总览层到任一轮分析的完整推理链，点击不超过 3 次；每一节点都能看到理论依据与证据来源。

### 5.5 理论模型库（WB-003，本次重点）

**入口**：总览层「查看理论依据」+ 任意理论标签。

**形态**：可搜索、可按环节/模型类型筛选的模型卡列表。

| 模型卡字段 | 说明 |
| --- | --- |
| 模型名 | 中文名 + 英文缩写（首次出现带释义） |
| 一句话定义 | 它到底在说什么 |
| 出处 | 来源与适用范围 |
| 在本产品哪一步使用 | 对应①-⑤中的环节 |
| **用在我身上的结论** | 引用当前用户的真实数据（如「你的霍兰德代码是 R-I-S，因此……」） |
| 关联的画像字段与维度 | 它读了哪些字段、影响哪几个 15 维维度 |
| 最近使用时间 | 增强「活资产」感受 |
| 反馈入口 | 「这个结论我认同 / 不认同」，写入行为日志并可触发增量重算 |

**至少覆盖的模型**：帕森斯（人职匹配）、霍兰德（RIASEC）、能力三核、舒伯（生涯发展阶段）、职业锚/价值观、三叶草、CD 职业发展模型、CASVE、决策平衡单、Vroom 择业动机、SMART、执行意图、克朗伯兹（计划性偶发）、班杜拉（自我效能）。

**禁止**：只显示名称、点开空白的「标签墙」。

### 5.6 交互特性（WB-005 及「气泡等等」）

1. **教练消息气泡流**：L1 的「今日/本周该做什么」区域为可滚动的气泡列表；每条气泡包含：触发原因（如「3 天未更新」）+ 一个最小可执行动作按钮 + 「稍后 / 不再提醒」。
2. **卡片 → 抽屉共享元素过渡**：点击环节卡或条目时，卡片元素连续放大为详情抽屉，关闭时回到原位。
3. **时间线可缩放**：日 / 周 / 月 / 学期四种视图切换，节点密度随缩放变化。
4. **版本对比**：v1 → v2 高亮变化点，并注明「因为更新了哪一项画像字段而变」。
5. **悬浮预览**：hover 维度、差距、任务可出轻量浮层，不强制进入二级页。
6. **键盘可达**：所有二级入口可用 Tab 聚焦、Enter 打开、Esc 关闭，焦点在关闭后回到触发元素。

## 七、推送（PSH）

### 7.1 目标与原则

推送是「陪伴教练」的触达手段，不是运营群发工具。三条不可违背的原则（源自 PRD §3.5 与 FR-REVIEW 序列）：

1. **只由真实信号触发**：任务停滞、节点临近、资料过期、学期/窗口切换。禁止系统自嗨式打扰。
2. **每条消息必须带一个最小可执行动作**：基调鼓励，不施压。
3. **打扰可控**：有冷却期、频率上限、免打扰时段与关闭入口。

### 7.2 需求明细

| 编号 | 需求 | 具体要求 | 优先级 |
| --- | --- | --- | --- |
| PSH-001 | 站内消息中心 | 顶栏铃铛入口 + 未读角标；消息列表按类型分组：教练提醒 / 节点提醒 / 导师建议 / 系统通知；支持单条已读、全部已读、点击跳转到对应环节 | P0 |
| PSH-002 | 教练主动消息气泡 | 在对话页与工作台以气泡形式出现（紫色系，与 CONV §4.6 共用组件）；每条含触发原因 + 一个最小行动按钮 + 「稍后 / 不再提醒」 | P0 |
| PSH-003 | 节点提醒 | 关键截止日可加入提醒；与关键节点日历联动；提醒时间可调（提前 7 天 / 3 天 / 1 天 / 当天） | P0 |
| PSH-004 | 通道分级 | 站内信（P0）→ 微信服务号或小程序订阅消息（P1）→ 短信（P2，仅关键节点）；各通道需用户显式授权 | P0/P1/P2 |
| PSH-005 | 触达规则 | 冷却期（同一类提醒最短间隔）、每日触达上限、免打扰时段、同一事件去重（同一信号不重复推） | P0 |
| PSH-006 | 通知偏好设置 | 用户可逐类开关（节点提醒 / 教练建议 / 导师建议 / 推广），可设置免打扰时段 | P0 |
| PSH-007 | 文案规范 | 结构固定：触发原因 + 一个最小行动 + 预期耗时；禁止焦虑化、施压式、夸大承诺用语 | P0 |
| PSH-008 | 推送埋点 | 下发、到达、打开、行动按钮点击、关闭偏好、退订 | P1 |

### 7.3 验收

1. 连续触发同一类信号时，用户不会在冷却期内收到重复消息。
2. 任一推送均可在消息中心找到，并可一键关闭该类推送。
3. 教练消息一定带有一个可执行的下一步动作。

- [ ] 桌面端页面本身不出现纵向滚动条。

4. **视觉风格是否允许升级？** 现令牌是「米白纸感 + 蓝绿双强调色」。你要求的「高级感/技术性」可能需要引入深色区块、渐变光晕、玻璃质感等元素，是否允许在现有令牌基础上扩展（还是必须完全沿用）？

9. **是否需要小程序 / App 端？** 若需要，本文档的移动端规则需要升级为多端方案。
10. **本期是否接入真实简历上传与解析？** 对话页输入区与首页首屏都有该入口。
11. **分析流程、理论模型库的数据来源**：由后端落库（推理链与模型使用记录），还是本期先用前端演示数据？这直接决定第三波排期。
