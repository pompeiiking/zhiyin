## 一、文档说明与边界

### 1.1 为什么独立成文

PRD 的主线是**业务语义**（三轴、五环节、智能体、黑板、需求编号与验收），而页面结构随交互迭代、评审节奏更快、参与角色不同（产品 / 设计 / 前端），绑定在同一份文档里会导致：

1. 改一处布局就要动 PRD 版本，评审成本外溢；
2. 页面规格与需求编号混排，前端难以定位「我只关心页面」；
3. 与 [原型设计说明.md](../../prototype/原型设计说明.md) 出现重叠却无明确归属。

拆出独立文档后，页面设计的读者、评审与版本周期都自成一条线。

### 1.2 对齐边界（谁负责什么）

| 主题 | 本文档负责（页面设计） | PRD 负责（业务语义） | 技术架构负责（实现） |
| --- | --- | --- | --- |
| 页面组成 | 页面清单、站点地图、导航层级、页面使命 | 页面承载的业务目标与验收（FR 编号） | BFF 聚合、路由与渲染方案 |
| 布局 | 三栏框架、栅格、滚动归属、区域职责 | — | 组件库、状态管理、SSE 通道 |
| 页面级交互 | 三态卡、长内容去向、显式告知位置、行为引导形态 | 交互背后的业务规则（如认领差距、可撤回选择） | 接口协议、事件推送 |
| 响应式 | 断点、移动端重排与降级规则 | 多端策略（Web 优先、P1+ 小程序/App） | 构建产物与适配技术 |
| 视觉 | 引用原型令牌，不重复定义 | — | — |
| 埋点 | 前端事件**触发时机与触发点** | 事件名、属性、指标口径（§十一） | 事件 schema、Kafka 路由 |

**防错耦合原则**：

1. 本文档不规定服务名、接口、数据库、事件 schema；不重述业务理论链（如「三叶草」「CASVE」只作为标签出现，含义以 PRD 为准）。
2. PRD 只规定「页面要达成什么」，本文档规定「页面如何呈现与交互」；两者通过 §九 映射表建立**唯一接触面**，不互相复制正文。
3. 页面结构调整若改变页面使命或环节归属，必须回写 PRD §4 页面总览与本文档 §九 映射表。
4. 术语与 PRD 严格一致：五环节（①采集②诊断③决策④行动⑤复盘）、三轴、智能体名称、黑板四件套。

### 1.3 阅读指引

## 二、设计总则

### 2.1 页面与三轴的映射

页面不是功能陈列柜，而是三轴的**可见投影**：

| 页面 | 承载哪根轴 | 使命 | 明确不为它做 |
| --- | --- | --- | --- |
| 首页 | 轴 A 定位器 + 任务入口 | 让用户说出「现在卡在哪」，路由到对应环节；顺带建立「为什么可信」 | 不做功能秀场、不堆输出能力数字 |
| 核心对话页 | 轴 B 前台执行面 | 完成一次微循环的实时交互 | 不承载长报告 / 资产管理 |
| 智能工作台 | 轴 A × 资产总控面 | 跨会话查看与操作「活资产」，长期分层管理 | 不做实时对话 |
| 完整报告页 | 资产全文视图 | 报告 / 方案 / 计划的只读全文与导出 | 不做交互式推进 |
| 功能块（导出 / 日历 / 成就 / 导师 / 身份 / 演示） | 挂在资产与产出上 | 外围服务 | 不占主线导航 |
| 登录 / 注册 | 全局 | 身份门槛与游客转正 | 不做业务引导 |

> 三轴定义、五环节命名与智能体职责见 [PRD §二、§三](../PRD/职引-PRD-v2.0.md)，本文档不重述。

### 2.2 页面总览

| 页面 | 编号锚点 | 身份可见性 | 优先级 |
| --- | --- | --- | --- |
| 首页 | `#screen-home` | 全身份 | P0 |
| 登录 / 注册 | `#screen-auth` | 全身份 | P0 |
| 核心对话页 | `#screen-conv` | 登录用户 | P0 |
| 智能工作台 | `#screen-wb` | 登录用户 | P0 |
| 完整报告页 | `#screen-report` | 登录用户 | P0 |

> **页面锚点口径**：以上锚点为全站唯一口径，[原型设计说明.md](../../prototype/原型设计说明.md) 与 `index.html` 已对齐（顶栏 id 为 `bar-conv` / `bar-wb` / `bar-report` 等）。原型页面内的可见文案（如「工作台」「个人数字智能体主页」）尚未按 PRD 术语改写，属后续「原型文案对齐」范围，不影响锚点与结构口径。

> **原型扩展页（PRD v2.0 未定义）**：[原型设计说明.md](../../prototype/原型设计说明.md) 中另有两个 PRD v2.0 未定义的页面——`#screen-subagent`（子智能体独立对话页，与 v2.0「智能体 = 能力池、不各自独占页面」相冲突）与 `#screen-mentor`（导师工作台，对应 PRD 的 P2 路线）。二者暂为原型演示扩展，不纳入本文档 P0 口径；若后续转正，须先回写 PRD 并同步更新 §九 映射表。

### 2.3 三条全局设计约束

1. **长内容不进对话流**：报告 / 方案 / 计划在对话中只给「最短结论 + 行为引导」，全文落到右栏管线卡与工作台资产；对话流永远短、可滚动、可返回。
2. **换主理必须显式告知**：中栏对话在换主理 / 换理论依据 / 结论变化时，必须出现一行可点开依据的解释，位置在中栏对话顶部（见 §4.2）。
3. **每轮以行为引导收尾**：任何一轮回复的结尾必须是「一个追问 / 一组选项 / 一个小任务 / 一条提醒」四选一，页面上必须存在对应的可点元素，禁止空转寒暄与无下一步的总结。

## 三、信息架构

### 3.1 站点地图

```
职引 ZHIYIN
├─ 首页 #screen-home（游客/用户可见，任务入口 + 信任建立）
│   ├─ 任务清单（迷茫/验证方向/拿不准/不知怎么动/卡住/复盘/直接开聊）
│   ├─ 示例报告（脱敏，标注演示数据）
│   └─ 顶栏：[登录/注册] 或 [头像·昵称·身份徽章]
├─ 登录/注册 #screen-auth（Modal 或独立页，P0）
├─ 核心对话页 #screen-conv（登录用户，P0）
│   ├─ 左栏：并行任务会话管理
│   ├─ 中栏：当前主理对话 + 行为引导
│   └─ 右栏：微循环管线卡（①-⑤）
├─ 智能工作台 #screen-wb（登录用户，P0，活资产总控）
│   ├─ ① 画像状态
│   ├─ ② 诊断与报告版本
│   ├─ ③ 方案与历史版本
│   ├─ ④ 计划与日历
│   ├─ ⑤ 跟踪与预警
│   └─ 功能块：报告全文/导出/日历/成就/导师/自动演示
└─ 完整报告页 #screen-report（挂在工作台资产上）
```

### 3.2 导航与全局框架

| 项 | 规则 |
| --- | --- |
| 顶层导航 | 仅「首页 / 核心对话页 / 智能工作台」三个主线页面互达；功能块不进主线导航 |
| 顶栏 | 常驻 [登录/注册] 或 [头像·昵称·身份徽章]；对话页顶栏额外承载任务名与主理徽章（见 §4.2） |
| 页面互达 | 首页 → 对话页（选任务）；对话页 ⇄ 工作台；工作台 → 完整报告页；任意页 → 首页 |
| 返回与恢复 | 页面往返**不销毁已生成资产、不重置对话进度**；重复进入沿用持久化的环节进度 |
| 演示入口 | 「自动演示」挂在工作台 / 演示入口，只读演示数据，不写真实黑板 |

### 3.3 身份与页面可见性矩阵

| 能力 | 游客 | 学生 | 导师 | 管理员 |
| --- | --- | --- | --- | --- |
| 浏览首页 | ✓ | ✓ | ✓ | ✓ |
| 查看脱敏示例 | ✓ | ✓ | ✓ | ✓ |
| 对话采集（完整） | 部分（≤2 问） | ✓ | — | — |
| 微循环全环节 / 工作台资产 | ✗ | ✓ | 只读（关联学生） | — |
| 导师建议 | ✗ | ✗ | ✓ | — |
| 平台配置 / 知识库 | ✗ | ✗ | ✗ | ✓ |

> 可见性只做**体验控制**；真实权限校验以技术架构为准。

## 四、页面级设计

> 各页 §「对应需求」列出的 FR 编号指向 [PRD §六](../PRD/职引-PRD-v2.0.md)；本文档只描述页面呈现与交互。

### 4.1 首页（`#screen-home`）

**对应需求**：FR-HOME-001 ~ FR-HOME-006

**设计意图**：首页主诉求是让用户用**自己的话**选任务，弱化「产品功能展示」。

**任务清单**（候选文案，需经真实用户语言化测试后再定稿）：

| 任务（用户说的话） | 路由到 | 主理开场 |
| --- | --- | --- |
| 还不太清楚自己适合什么 | ① 采集建模 | 建档分析师，一次一问 |
| 想验证某方向行不行 | ② 诊断匹配 | 职业顾问（按需调侦查员） |
| 几个方向拿不准 | ③ 决策 | 职业顾问 |
| 定了方向不知道怎么动 | ④ 行动 | 路径规划师 |
| 执行卡住了 / 没进展 | ⑤ 复盘（先判别） | 陪伴教练 → 视判别转其他主理 |
| 好久没管了 / 该复盘了 | ⑤ 复盘 | 陪伴教练 |
| （兜底）直接开聊 | 意图识别 → 自动入环 | 编排器判定 |

**页面结构**：

```
┌ 顶栏：logo · [登录/注册] 或 [头像·昵称·身份徽章] ┐
├ 主区：一句话定位（用户视角，非功能列表）        │
├ 任务卡组：7 个任务入口（用户语言，点击即路由）    │
├ 信任区：「每步都基于职业咨询成熟方法」单条主线     │
│         + 可点开的方法论示例（示例报告，脱敏）    │
└ 页脚：数据来源与方法论脚注                       ┘
```

**规则**：

- 「为什么可信」只讲一条主线：你做的每步都基于职业咨询的成熟方法（可点开示例）；**不讲** 15 维 / 3 套 / 5 分钟这类数字炫技。
- 兜底「直接开聊」入口常驻，识别不准时回落到澄清问题，不硬跳环节。
- 身份决定可见内容：游客引导注册、学生全任务、导师进导师视图。

### 4.2 核心对话页（`#screen-conv`，三栏编排）

**对应需求**：FR-CONV-001 ~ FR-CONV-007

```
┌ 顶栏：当前任务名 · 当前主理智能体徽章（含依据说明） · 闭环进度 ┐
├──────────────┬────────────────────────────┬──────────────────┤
│ 左栏 会话管理 │ 中栏 对话（当前主理）        │ 右栏 微循环管线卡  │
│ · 并行任务会话 │ 当前智能体气泡（理论可点开） │ ①采集▸②诊断▸③决策 │
│   （各标所处环节 │ 用户气泡/快捷行为          │ ▸④行动▸⑤复盘     │
│    与完成度）   │ 底部：行为引导（选项/小任务）│ 每环节一卡，三态： │
│ · 可新建/续接  │                           │ ①当前产出          │
│ · 可点历史会话  │                           │ ②可展开·理论模型   │
│              │                           │ ③可展开·评价状态   │
└──────────────┴────────────────────────────┴──────────────────┘
```

**规则**：

- **三栏固定框架**，左右两栏内部滚动，中栏对话正常滚动；
- **长内容不进对话流**：报告 / 方案 / 计划只在中栏给「最短结论 + 行为引导」，全文进右栏卡与工作台资产；
- **换主理显式告知**：中栏对话顶部出现一行说明，例：「以下由职业顾问接手，依据帕森斯人职匹配，因为你需要的是方向验证」；理论标签可点开模型卡；
- **会话命名**：左栏会话按**任务 / 环节**命名（如「建档·进行中」「秋招方向验证·已完成」），**不按 agent 名**排布；每项显示所处环节与完成度；
- **右栏管线卡三态**：①当前产出 ②可展开的理论模型 ③可展开的评价状态；①-⑤ 每环节一卡，当前环节高亮；
- **行为引导区**：中栏底部固定承载追问 / 选项 / 小任务 / 提醒四类引导的可点元素。

### 4.3 智能工作台（`#screen-wb`，跨会话资产总控）

**对应需求**：FR-WB-001 ~ FR-WB-007

**页面结构**：

```
┌ 顶栏：当前身份 · [进入对话页] · [登录/注册] ┐
├ ① 画像状态（字段覆盖度 / 置信度 / 缺口 / 更新时间）│
│ ② 诊断与报告版本（含历史版本与 diff）             │
│ ③ 当前方案（含历史版本）                          │
│ ④ 计划与日历                                      │
│ ⑤ 跟踪与预警（教练消息汇总）                      │
│ 功能块：报告全文/导出 · 日历 · 成就 · 导师 · 演示  │
└──────────────────────────────────────────────┘
```

**规则**：

- **按环节分层**：① 画像状态、② 诊断与报告版本、③ 当前方案（含历史版本）、④ 计划与日历、⑤ 跟踪与预警，另挂成就与操作块；
- **每个节点卡三态**：当前评价状态 / 可展开的理论模型 / 历史与差异（如「v2 因更新了 X 而变化」）；
- **分层可收缩展开**；整体允许按轴 A 阶段过滤；
- **教练消息集中呈现**：陪伴教练的主动消息（提醒 / 预警 / 复盘邀请）在此汇总，也可 push 到对话页；
- **数据闭环可视化**：展示画像-报告-方案-计划-行为日志之间的依赖与「上次更新 / 下次该更新」；
- 内容按轴 A 阶段排序优先（阶段推断属于后台，前台不需用户选阶段）。

### 4.4 完整报告页（`#screen-report`）

**对应需求**：FR-BLOCK-001

- 入口：工作台资产 →「报告全文 / 查看完整报告 →」；
- 形态：左侧目录导航 + 右侧全文只读（含 15 维全景、方案、行动计划、个人画像）；
- 只读资产视图，不承载实时对话与推进；顶栏提供导出（Word / PDF）；
- 报告全文页读取资产版本，版本变化时展示变化点（diff 展示属工作台职责，本页仅呈现结果）。

### 4.5 登录 / 注册（`#screen-auth`）

**对应需求**：FR-AUTH-002 ~ FR-AUTH-004

- 形态：Modal 或独立页，P0；
- 内容：手机号 + 验证码（未注册自动建号）、协议勾选（用户协议 / 隐私政策，未勾选不可提交）；
- 入口：首页与对话页 / 工作台顶栏常驻；
- 游客转正：登录后把游客已采集字段合并到真实画像，冲突以用户确认值为准（合并逻辑属业务，见 PRD FR-AUTH-005）。

### 4.6 功能块挂载点

| 功能块 | 挂在哪 | 读写谁 |
| --- | --- | --- |
| 登录 / 身份 | 全局 | 决定可见性 |
| 报告全文 / 导出 | 工作台资产 → 全文页（§4.4） | 读资产版本 |
| 关键节点日历 | 工作台 + 提醒通道 | 规划师写入、教练读取 |
| 成就体系 | 工作台 | 只读行为日志 |
| 导师共享 / 建议 | 工作台（学生资产只读 + 写建议） | 建议写入行为日志 → 可触发教练动作 |
| 自动演示 | 工作台 / 演示入口 | 只读演示数据，不写真实黑板 |

## 五、页面状态与流转

### 5.1 页面与容器状态清单

| 页面 / 容器 | 状态 | 说明 | 归属 |
| --- | --- | --- | --- |
| 核心对话页 · 右栏 | `当前产出 / 理论模型展开 / 评价状态展开` | 每环节卡三态，同一时刻每卡最多展开一层 | 本文档 §4.2 |
| 智能工作台 · 节点卡 | `当前评价 / 理论模型 / 历史 diff` | 三态可切换 | 本文档 §4.3 |
| 对话页 · 顶栏 | `主理徽章 + 依据` | 换主理时同步刷新并出现显式告知行 | 本文档 §4.2 |
| 登录拦截 | `未触发 / 已拦截（弹登录）` | 见 §5.3 | PRD §5.1 |
| 游客受限采集 | `已答 0–2 问 / 超限拦截` | 超过 2 问进入登录拦截 | PRD §5.1 |

### 5.2 入口与会话恢复

- 用户可反复往返首页、对话页、工作台，**不销毁已生成资产**；
- 重新进入某任务会话时，沿用持久化的环节进度与前序资产，不重复问、不整篇重生成；
- 左栏新会话与历史会话均可进入；进入历史会话时右栏按该会话所处环节定位。

### 5.3 游客拦截点

触发以下**持久化行为**前弹出登录：生成诊断 / 方案 / 计划、导出、进入工作台、采集超过 2 问。拦截前用户已输入的内容不丢失，登录后继续。

## 六、响应式与多端

### 6.1 断点

| 断点 | 适用 | 主要变化 |
| --- | --- | --- |
| > 900px | 桌面 | 三栏 / 双栏完整布局 |
| 900px | 平板竖屏 / 小笔记本 | 对话页右栏转为抽屉或收窄，工作台分层改为单列堆叠 |
| 640px | 大屏手机 | 顶栏允许换行分组，卡片单列 |
| 560px | 小屏手机 | 会话管理左栏转为顶部分组入口，管线卡转步骤条 |

### 6.2 核心对话页的窄屏重排

屏宽受限时，三栏**转为分层抽屉 / 步骤条**，保证**对话主区优先**：

- 左栏会话管理 → 顶部会话切换入口（抽屉 / 下拉）；
- 右栏管线卡 → 可横滑的步骤条 + 展开面板；
- 中栏对话始终为视觉主区，行为引导区吸底。

> 移动端 Tab + 页面栈的完整重排方案见 [移动端原型技术方案.md](../../prototype/移动端原型技术方案.md)，本文档只约束「桌面三栏 → 窄屏」的降级规则与优先级。

### 6.3 无障碍

- 关键操作（提交、认领差距、选择方案、勾选任务）支持**键盘可达**；
- 对比度符合 **WCAG AA**；
- 主要可点元素（按钮 / 快捷选项 / 卡片）在窄屏下保证足够触控面积。
