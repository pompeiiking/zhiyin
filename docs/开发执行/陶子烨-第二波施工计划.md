## 二、施工内容

### 2.1 Axis A

新增 `business/policies/axis_a.py`。规则只读黑板事实，优先使用最近的停滞、重选、复盘、任务完成事件，再读取目标方向；证据不足返回空，由编排器使用动态注册表中的阶段理论能力智能体执行模型兜底。前台不增加轴 A 选择入口。

### 2.2 路由与交接

编排器使用 `StateStore` 保存会话级澄清次数，并从 `policy_params.routing` 读取次数和回落环节。参数缺失、未确认或非法时明确失败。交接抽成私有统一执行路径，公开 Port 签名保持不变。

### 2.3 资产正文

| 环节 | 产出 | 写入接口 | 关键关联 |
| --- | --- | --- | --- |
| ②诊断 | `Report` | `save_report` | 正文版本与 AssetVersion 一致 |
| ③决策 | `list[DirectionPlan]` | `save_direction_plans` | 关联最新报告，不存在则留空 |
| ④行动 | `ActionPlan` | `save_action_plan` | 仅关联用户已选择的方向 |

方向产出里的字符串差距按兼容规则写入 `PlanGap.requirement`，现状和建议留空，不擅自补写用户事实。

### 2.4 知识来源

诊断和决策使用用户原始消息加当前主理的动态理论卡构造查询，仅检索 `theory` 命名空间。Agent 可看到完整命中上下文；返回前端的理论引用只从真实 KnowledgeHit 转换，报告来源优先使用命中的 `source_url` 或 `source`。

## 四、施工顺序与风险

1. 新增 Axis A 规则并补独立单测。
2. 修改编排回合、澄清计数和交接路径。
3. 接通三类资产正文和知识检索。
4. 在 Boot 注入 Axis A 策略、KnowledgeGateway、StateStore。
5. 把 OPEN-1、OPEN-2 迁移为正式 e2e。
6. 完成全量门禁和同事复核。

主要风险：

- `RegistryLeadPolicy` 当前仍只按环节选择主理，尚未真正消费 Axis A 和意图；由赵天硕按既有签名补齐。
- `PlanOption.gaps` 与 `PlanGap` 信息粒度不同，本轮只做无损可解释的最小兼容映射。
- `boot/container/services.py` 是装配热点，本轮只增加三项注入，需平台负责人复核。
- 当前前端依赖未安装时，必须先执行 `npm ci`，不能把 `vue-tsc` 缺失误判为代码失败。
