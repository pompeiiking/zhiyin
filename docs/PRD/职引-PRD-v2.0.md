### 1.4 与《职引技术架构文档》的对齐边界

本 PRD 与 [职引技术架构文档.md](../技术架构文档/职引技术架构文档.md) 共同使用以下唯一口径，避免产品语义与技术实现错耦合：

| 主题 | PRD 负责（产品语义） | 技术架构负责（技术实现） |
| --- | --- | --- |
| 三轴模型 | 定义轴 A、轴 B、轴 C 的含义与业务规则 | 定义阶段推断、环节状态机、编排器调用链 |
| 五环节 | 定义 ①采集→②诊断→③决策→④行动→⑤复盘 的命名、四元组与防跑偏规则 | 定义 Loop Service、任务会话、环节切换与持久化 |
| 智能体 | 定义五个智能体的理论包、可做/不可做、被调用场合 | 定义 agent_registry、output_contract、Agent.invoke |
| 黑板 | 定义画像活状态、行为日志、会话记忆、资产影响面的业务含义 | 定义 MySQL/Redis/Kafka 落点、一致性与读写顺序 |
| 影响面传播 | 定义哪些行为触发增量重算、版本 diff 的用户可见语义 | 定义 Worker、资产版本表、只重算受影响片段 |
| 页面 | 定义页面承载的业务目标、环节归属与需求验收（FR-HOME/CONV/WB）；页面信息架构、布局、交互与可见性以《职引-前端页面设计》为唯一口径 | 定义 BFF、SSE/WS、Notify 与前端接口 |
| 指标埋点 | 定义北极星、行为事件与产品指标 | 定义行为日志事件 schema、Kafka 路由与存储 |

防错耦合原则：

1. PRD 不规定服务名、存储选型、数据库表；技术架构不规定用户可见文案、环节理论链、行为引导口径。
2. 双方使用同一组术语：五环节、三轴、智能体名称、黑板四件套必须完全一致。
3. 任何一侧变更术语或边界，必须同步更新另一侧的「对齐边界」表。

## 二、产品定义与北极星

### 2.1 一句话定位

面向个人的「多智能体服务群 + 功能块 + 长期闭环」个性化耦合体；职业咨询理论是**流程编排的骨架**（不是事后贴的标签）；北极星 = 用户**行为在变、认知在长、持续在用**；产品形态 = A+C（把专业咨询方法产品化 × 做用户的成长教练）。

### 2.2 A+C 形态带来的两种使用模式

| 模式 | 触发 | 主要停留环节 | 形态 |
| --- | --- | --- | --- |
| 决策模式（低频高价值） | 遇到岔路口、方向存疑 | ② 诊断匹配、③ 决策 | 产出方案与可撤回选择 |
| 陪伴模式（高频长期） | 日常推进、停滞、节点到期、学期末 | ④ 行动、⑤ 复盘校准 | 小任务 + 提醒 + 复盘 |

两种模式共用同一条微循环管线，只是进入点与停留环节不同。产品必须支持「可拆可续」：从任意环节进入，前序资产自动继承，不重复问、不整篇重生成。

### 2.3 三轴模型总览

| 轴 | 是什么 | 节奏 | 显隐性 |
| --- | --- | --- | --- |
| 轴 A · 用户职业发展进程 | 用户此刻处在生涯哪一段（探索→定向→冲刺→适应→再定位） | 月~年 | **隐性**，后台推断，只用于调开场与工作台分层 |
| 轴 B · 服务微循环 | 一次求助/一次交互都走的公共管线（①采集→②诊断→③决策→④行动→⑤复盘） | 秒~分钟 | **显性**，是页面与对话的共同骨架 |
| 轴 C · 能力与编排 | 智能体=能力池、功能块=外围服务、黑板=共享状态、编排器=选主理 | 引擎 | 对用户只露「当前是谁在帮我、为什么」 |

### 2.4 四元组判据

任何内容想成为「一层 / 一个节点 / 一张卡 / 一个页面模块」，必须能填满四元组：

> **用户此刻的行为/卡点 → 用哪套理论解读 → 推理产出什么 → 产出推动用户哪一个下一步行为**

产出的「下一步」若不是用户行为而是另一份报告，则不配单独成层。所有功能需求验收时都要回到这四元组。

### 2.5 三个已确认决策

1. 产品定位 A+C：低频高价值决策 × 高频长期陪伴；
2. 北极星是「行为改变与认知成长、持续使用」（教练逻辑），不是「单次决策正确率」；
3. 理论模型是**真推理内核**（可复现、可追溯、每步可展开），智能体按理论流程产出，AI 自由发挥后贴标签的做法被否定。

### 2.6 北极星与成功指标

北极星不是「他做了多正确的选择」，而是：

| 维度 | 可观测指标 |
| --- | --- |
| 持续回来 | 次周/次月/次学期回访率；主动更新资料次数 |
| 行为事件 | 认领差距次数、做出可撤回选择次数、勾掉任务次数、完成复盘次数 |
| 认知变化 | 用户开始使用「能力/兴趣/价值/差距」的语言描述自己，能讲出「我的依据」的比例 |
| 干预有效 | 预警后行为恢复率；停滞率下降 |
| 闭环再入 | 画像更新后触发影响面传播与增量重算的次数；微循环再入环次数 |

### 2.7 它不是什么（防跑偏对照）

| 容易滑向 | 为什么不是 |
| --- | --- |
| 报告生成器 | 报告是中间产物；北极星是行为改变，不是「出报告」 |
| 通用 AI 聊天 | 通用聊天无结构化采集、无理论骨架、无跨会话记忆；本产品每一步都要锚定「环节+理论」 |
| 一次性测评工具 | 测评只是采集手段之一；画像是随行为**持续增量维护**的活状态，不是填完即固定的结果 |
| 单智能体客服 | 不存在一个「什么都会的助手」；由编排器按情境自动组队并显式告知 |

## 三、业务模型与运行时逻辑

### 3.1 轴 A · 用户职业发展进程（隐性）

| 阶段 | 用户状态与要解决的问题 | 系统在后台应做的 | 影响哪些前台表现 |
| --- | --- | --- | --- |
| 探索自我 | “我是谁、适合什么” | 侧重 ① 采集，多角度提问 | 开场话题、画像缺口提示、工作台排序 |
| 验证/定向 | “某方向到底行不行” | 侧重 ②③，多套方案对比 | 诊断深度、方案数量 |
| 冲刺行动 | 决策窗口（秋招/考试/申请） | 侧重 ④，节点日历、投递节奏 | 节点提醒密度、任务粒度 |
| 适应成长 | 已入场，0–3 年校准 | 侧重 ④⑤，复盘与微调 | 复盘频次、成就体系 |
| 受挫再定位 | 执行停滞或方向动摇 | 先判别再重跑 ②③ | 教练主动介入 |

**规则**：轴 A 由系统根据画像、行为日志、外部窗口推断；**前台不要求用户选阶段**。它改变的是「同一环节被服务的深度与口气」，不是新增页面层级。

### 3.2 轴 B · 服务微循环（显性骨架）

```
 ①采集建模 → ②诊断匹配 → ③决策 → ④行动 → ⑤复盘校准 ──┐
     ↑                                        │
     └────────── 用户新行为 / 画像更新 ─────────┘（再入环）
```

**环节定义**：

| 环节 | 一句话 | 主理 |
| --- | --- | --- |
| ① 采集建模 | 把用户零散信息沉淀成带「置信度/缺口」的结构化画像 | 建档分析师 |
| ② 诊断匹配 | 画像 × 目标要求 → 现状、差距、卡点诊断 | 职业顾问 |
| ③ 决策 | 在方向/选项间做「可撤回的选择」 | 职业顾问 |
| ④ 行动 | 把选择拆成带日历、能勾掉的行动 | 路径规划师 |
| ⑤ 复盘校准 | 盯执行、给反馈、触发再入环 | 陪伴教练 |

**可拆可续规则（已确认）**：

- 首次进入或表达迷茫 → 系统引导走完整管线；
- 日常从**任意环节**进入（用户自己选任务，或教练/顾问推荐）；
- 前序产出自动继承：画像在案、报告在案，**不重复问、不整篇重生成**；
- 环节进度跨会话持久化（这就是「续」）。

### 3.3 轴 C · 能力与编排（引擎）

**智能体 = 能力池**（不再各自独占一个「层」）：

| 智能体 | 拥有的理论包 | 知识/工具 | 被调用的场合 | 明确不做 |
| --- | --- | --- | --- | --- |
| 建档分析师 | 帕森斯·了解自我；霍兰德·自我代码；能力三核；舒伯·阶段/角色；职业锚·价值取向 | 访谈话术、画像字段 schema、测评解释 | 任何环节发现画像缺信息/置信度低时 | 不替用户下判断 |
| 职业顾问 | 帕森斯·匹配；CD·发展状态；三叶草；CASVE（分析/综合/评估）；决策平衡单；Vroom | 职业库、岗位要求、差距算法、方案生成 | 诊断、多方案、方向存疑判别 | 不替用户执行 |
| 路径规划师 | SMART；执行意图（if-then）；克朗伯兹·计划性偶发 | 节点日历、窗口模板、任务拆解 | 决策落地成计划、计划重拆 | 不评判方向对错 |
| 陪伴教练 | 舒伯·发展观；班杜拉·自我效能；克朗伯兹 | 行为日志、节律、提醒通道、成就体系 | 主动干预、复盘、停滞预警（唯一可主动发起会话者） | 不越界代产出诊断/方案 |
| 信息侦查员 | （无认知理论，供事实） | 学职平台库、JD、行情、时间窗口 | 任何环节需外部事实时被按需调用 | 不与用户闲聊、不给建议 |

**功能块 = 能力池外的外围服务**：登录/身份（游客·学生·导师；管理员为平台配置角色）、报告全文与导出、关键节点日历、成就体系、导师共享/建议、自动演示。

挂载规则：身份决定可见性；日历被规划师写入、被教练读取；成就只由**行为日志**驱动（防自嗨）；导出挂在工作台资产上。

**黑板 = 共享状态**（所有智能体读写同一份）：

1. 个人画像（**活状态**：字段值 + 置信度 + 缺口 + 更新时间线）；
2. 行为日志（事件流：作答、认领、选择、勾任务、停滞、更新资料）；
3. 会话记忆（各任务会话摘要）；
4. 资产版本与影响面（报告/方案/计划的版本 + 各自依赖哪些画像字段）。

**编排器 = 决策规则**，职责：

1. 识别用户意图 → 判定当前所在环节（轴 B）；
2. 按（轴 A 阶段 × 轴 B 环节 × 意图）选择**主理智能体**（及协理/信息侦查员）；
3. 定义跨智能体**交接**（产出契约 + 触发条件）；
4. 维护黑板一致性：画像更新 → 影响面传播 → 增量重算；
5. 调度主动事件（教练提醒、节点到期、停滞超时）；
6. 生成「显式告知」文案（换主理/换理论依据时对用户说明）。

### 3.4 三轴如何合成一次服务

> 每次用户输入 → 编排器在轴 A 上读取「他现在是谁」、在轴 B 上判定「他要走哪一环」、在轴 C 上点兵（谁主理、谁协理、调不调侦查员）→ 按环节的理论链产出 → 落成行为引导 → 结果写回黑板。

任何时刻用户只感知三件事：

1. **现在是谁在帮我**（主理 + 徽章）；
2. **依据什么**（理论，可点开）；
3. **我下一步做哪个动作**（行为引导）。

### 3.5 各环节四元组

| 层 | 用户行为/卡点（采什么） | 服务理论链 | 推理产出 | 产出推动的下一步行为 |
| --- | --- | --- | --- | --- |
| ① 采集建模 | 自述、简历/作品、对追问的作答；长期的所有选择与完成记录 | 帕森斯·了解自我；霍兰德·自我代码；能力三核；舒伯·阶段与角色；职业锚·价值取向 | 增量个人画像：字段值 + **置信度** + 缺口清单 | 补一条信息 / 做一个小测评 → 画像置信度提升 |
| ② 诊断匹配 | 想看「我离想去的地方差在哪」 | 帕森斯·匹配；CD·发展状态；三叶草 | 15 维现状 + SWOT + **差距清单** | 让用户**认领 3 条差距** |
| ③ 决策 | 在几个方向/选项间比较、犹豫 | CASVE；决策平衡单；Vroom | 主攻/平行/保底 3 套 + 每套取舍依据 | 让用户做出**可撤回的选择** |
| ④ 行动 | 定了方向但不知下一步做什么 | SMART；执行意图；克朗伯兹·计划性偶发 | 阶段里程碑 + 带日历的小任务 + 节点提醒 | 让用户**勾掉第一个小任务** |
| ⑤ 复盘校准 | 停滞/受挫/节点到期/学期末 | 舒伯·发展观；班杜拉·自我效能；克朗伯兹 | 进度/预警/归因/成就 → 触发 ①-④ 的**增量重算** | 让用户做一次小行动或更新画像 → **再入环** |

**横切层**：信息侦查员向 ①②④ 的任何环节供「外部事实」（岗位要求、行情、窗口），它自己不成层、不进对话主线。

**各层防跑偏注记**：

- ①：目标是「画像置信度提升」，不是「问完 6 个问题收工」；
- ②：产出必须收敛到「用户认领差距」，不能停在「我帮你分析完了」；
- ③：给「可撤回的选择 + 依据」，不给「唯一正确答案」，不许用话术诱导选贵的/选系统偏好的；
- ④：任务是「今天/本周勾得掉」的粒度，拆不动就回到 ② 检查是不是方向问题；
- ⑤：只由**行为日志**驱动（3 天无动作、节点临近等真实信号），不允许「系统自嗨式打扰」。

### 3.6 运行时走查

**场景 A · 首次 · 迷茫 · D0**

1. 首页：点「还不太清楚自己适合什么」；
2. 对话页：建档分析师开场（显式告知身份），一次一问，右栏 ① 画像卡覆盖/置信度逐题增长；
3. 画像置信度达标 → 交接告知 → 职业顾问主理诊断：右栏 ② 卡出 15 维与差距，用户**认领 3 条差距**；
4. → ③ 决策卡出 3 套方案，用户选主攻；
5. → ④ 规划师出计划卡，用户勾第一个小任务；
6. 沉淀：黑板（画像 v1、报告 v1、方案、计划、行为日志），工作台分层刷新；教练在后台登记节点与停滞观察。

**场景 B · 老用户 · D21 · 停滞**

1. 事件：3 天无任务勾选 → 陪伴教练主动发起 → 工作台/对话页出现教练消息；
2. 教练判别停滞归因（任务太大 / 动机不足 / 方向动摇）：
   - 方向动摇 → 显式交接给职业顾问（不重跑全流程，只增量重算）；
   - 任务太大 → 交路径规划师拆成「5 分钟任务」；
3. 产出：一个立即能勾掉的小任务 → 行为日志 +1 → 成就/进度刷新。

> 全程没有生成任何新报告，但北极星指标在涨——这就是「教练逻辑」与「报告逻辑」的区别。

**场景 C · 方向存疑**

1. 用户：「投了一堆没回音，是不是方向错了？」
2. 职业顾问判别：**执行问题还是匹配问题**（读画像 × 岗位差距 × 投递行为）；
   - 匹配 OK、简历/渠道差 → 只更新 ④ 行动，不动方向；
   - 确实不匹配 → 回 ②③ 增量重跑，报告 v2 标注变化点。

### 4.2 三条全局设计约束（业务底线）

页面如何呈现以《职引-前端页面设计》为准，此处只声明不可违背的业务底线：

1. **长内容不进对话流**：报告/方案/计划在对话中只给「最短结论 + 行为引导」，全文落右栏卡与工作台资产；
2. **换主理必须显式告知**：换主理/换理论依据/结论变化时，须对用户说明原因且依据可点开；
3. **每轮以行为引导收尾**：结尾必须是「追问 / 选项 / 小任务 / 提醒」四选一。

> 首页任务清单、三栏布局、站点地图、功能块挂载点、页面可见性矩阵、响应式断点与无障碍等实现级规格，见 [职引-前端页面设计-v1.0.md](../前端设计/职引-前端页面设计-v1.0.md)。

## 五、端到端用户旅程与状态机

### 5.1 公共状态机（按微循环而非线性报告）

```
[未登录·游客]
   │ 浏览首页 / 示例报告 / 受限对话（≤2 问）
   │ 触发持久化行为（生成诊断/方案/计划/导出/进入工作台）→ 登录拦截
   ▼
[已登录·学生]
   │ 首页选任务 或 直接开聊
   ▼
[编排器判定]
   │ 轴 A 推断当前阶段 + 轴 B 判定目标环节 + 轴 C 选主理
   ▼
[进入任一环节]
   │ ① 采集建模 ⇄ ② 诊断匹配 ⇄ ③ 决策 ⇄ ④ 行动 ⇄ ⑤ 复盘校准
   │ 环节间由编排器显式交接，前序资产自动继承
   ▼
[写回黑板]
   │ 画像/行为日志/会话记忆/资产版本更新
   ▼
[智能工作台刷新]
   │ 按 ①-⑤ 分层展示活资产、理论依据、历史差异
   ▼
[主动事件 / 新行为] → 再入环
```

**关键状态说明**：

- 游客只能体验 ① 采集的前 2 问；触发核心产出或持久化操作前须登录，临时画像登录后合并（见 FR-AUTH）。
- 「可拆可续」要求系统状态不只记录“报告是否生成”，还要记录“当前在哪一环节、哪些前序资产可用、哪些画像字段影响了该资产”。
- 用户可反复往返首页、对话页、工作台，不销毁已生成资产。

## 八、智能体能力池与编排规则

### 8.1 实现路径

P0 采用「角色分层提示词 + 共享黑板上下文」实现编排体感，不引入 LangGraph/CrewAI 等重级框架；当出现多轮协商、并行工具调用、复杂交接时再评估编排框架。

### 8.2 单轮回复骨架

每次 AI 回复必须走 5 步：

1. 读黑板：画像、行为日志、当前会话上下文；
2. 环节判定：落在轴 B 哪一环、该环要回答的问题是什么；
3. 选主理：环节主理（必要时协理 + 调侦查员）；
4. 理论链产出：按该环节理论链组织证据 → 产出契约（结构化），对话内只给最短结论；
5. 行为引导收尾：结尾必须是追问 / 选项 / 小任务 / 提醒之一。

### 8.3 协作与交接触发规则

| 触发 | 动作 | 是否显式告知 |
| --- | --- | --- |
| 采集置信度达标 / 用户说「帮我看看行不行」 | 建档分析师 → 职业顾问 | 是 |
| 用户在行动期问「现在投哪些岗」 | 路径规划师主理 + 调侦查员（必要时顾问协理）→ 收敛为 2-3 条行动 | 告知依据 |
| 用户 3 天无动作 / 节点到期 | 陪伴教练主动发起，归因 + 最小行动干预 | 是 |
| 用户说「方向是不是选错了」 | 顾问先判别执行问题 vs 匹配问题，匹配问题才重跑 ②③ | 告知判别结论 |
| 画像任一字段更新 | 影响面传播 → 受影响资产增量重算并标注 | 告知「已按新信息更新 v2」 |

### 8.4 主动事件守则

- 触发只来自真实信号：任务停滞超时、节点临近、资料过期、学期/窗口切换；
- 有打扰度上限与冷却期，教练消息必须带「最小可执行动作」；
- 触发后仍走 ⑤ 复盘主理逻辑，不越权产出 ②③ 结论。

### 8.5 一致性与影响面传播

- 每个资产记录它依赖哪些画像字段；
- 字段更新 → 只重算受影响片段，资产版本 +1，diff 展示；
- 不做「整篇重新生成」。

### 8.6 可解释性（显式告知三种场合）

1. 换主理：说明为什么现在是这个智能体；
2. 换理论依据：说明这一次判断用的理论链，可点开模型卡；
3. 结论变化：说明「因为哪条新信息，什么结论变了」。

### 8.7 Prompt 与知识库关系

Prompt 需显式注入：(a) 用户画像活状态 JSON；(b) 对应知识库检索结果；(c) 方法论骨架说明。输出必须结构化、可解释、可溯源，不自由发挥。

### 14.2 术语表

| 术语 | 定义 |
| --- | --- |
| 轴 A | 用户职业发展进程（隐性，长期） |
| 轴 B / 微循环 | 一次服务的公共管线：①采集②诊断③决策④行动⑤复盘 |
| 环节 | 微循环中的一个阶段 = 一个业务节点 |
| 主理 | 本次对话/本环节主导输出的智能体 |
| 协理 | 后台配合主理完成特定子任务的智能体 |
| 黑板 | 画像（活状态）+ 行为日志 + 会话记忆 + 资产版本影响面 |
| 画像活状态 | 随行为持续增量维护、带置信度与缺口的个人结构化状态 |
| 产出契约 | 智能体交接时约定好的结构化产出格式 |
| 影响面传播 | 画像字段更新后，只重算依赖它的资产片段 |
| 显式告知 | 换主理/换理论/结论变化时对用户说明原因 |
| 功能块 | 身份/导出/日历/成就/导师等外围服务 |
| 可拆可续 | 微循环可从任意环节进入，前序产出自动继承，进度跨会话持久 |
