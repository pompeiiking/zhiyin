## 1. 背景与目标

[职引技术架构文档.md](../docs/技术架构文档/职引技术架构文档.md) §1.2 明确「Web 优先，首期响应式（断点 900/640/560px）；P2 才扩展小程序 / App」。现有 `index.html` 已经补了部分响应式断点，但仍是「桌面多栏布局硬挤到小屏」的思路：顶栏 + 返回链接、侧栏画像抽屉、双栏报告页在窄屏下只是降级堆叠，不是按移动端用户习惯的交互范式设计的。

本方案的目标：在**不改变现有产品信息架构与业务逻辑**（对话式建档 → 15 维解析 → 方向方案 → 行动计划 → 长期跟踪 → 5 个子智能体）的前提下，产出一份**按移动 App/H5 心智重排**的独立高保真原型，用于团队评审与用户测试，同时为 P2 小程序/App 开发提前验证导航结构与信息密度。

---

## 2. 技术选型与运行方式

- **单文件、零依赖**：与桌面版一致，纯 HTML + 内联 `<style>` + 内联 `<script>`，不引入构建工具、不依赖任何 CDN/框架，保证离线可运行、可直接发给任何人双击打开。
- **视口**：`<meta name="viewport" content="width=device-width,initial-scale=1,viewport-fit=cover">`；设计基准宽度 375px（iPhone 标准），兼容 360–430px（主流 Android / iPhone Pro Max）。
- **手机外壳（可选）**：URL 参数 `?frame=1` 触发 `.device-frame` 包装层（圆角机身 + 顶部状态栏 + 底部 Home Indicator 装饰），仅用于桌面浏览器演示截图；无参数或在真实移动浏览器打开时，页面即是标准全屏移动网页，不显示任何机身装饰。
- **不做真实手势**：与桌面版一致，保持"点击驱动"演示原则（不实现真实的左滑返回、下拉刷新等手势），页面切换用 CSS transition 模拟"原生 push/pop"的视觉效果。

## 3. 与桌面原型的关系

| 维度 | 处理方式 |
| --- | --- |
| 视觉令牌（颜色/字体/圆角/阴影） | 直接复用 `index.html :root` 中的 CSS 变量表，不重新设计视觉风格，保证「同一产品的两种形态」 |
| Mock 业务数据 | 直接复制 `index.html` 中的数据对象：`DIMS`、`GAP_ROWS`、`CLOVER`、`CD_MODEL`、`PLAN_DIMS`、`PLAN`、`GROUPS`、`QUESTIONS`、`SUBAGENTS`、`SUBAGENT_CHATS`、`STUDENTS`、`PROFILE_DEMO`、`USERS` 等，保证两版内容一致，评审时不会「数据打架」 |
| 渲染函数 | 复用桌面版已抽象好的纯函数（`dimStats`/`renderDimCard`/`renderVerdictBlock`/`renderCloverModel`/`renderCDModel`/`buildReportHtml`/`planCard` 等），**容器由移动端布局层重新包裹**，内容与结论文案保持一致 |
| 交互范式 | **不复用**桌面的顶栏返回链接 + 侧栏 + 双栏栅格；改为移动端原生范式（见 §4、§5） |

## 4. 信息架构：底部 Tab + 页面栈

采用移动端标准的「Tab 根页 + 栈式二级页」双层导航模型：

```
┌ 应用外壳 .app-shell ──────────────────────────┐
│ ┌ 顶部 Header（标题 / 返回按钮 / 右侧操作）──┐ │
│ ├ 页面内容区（当前激活的 .m-page）──────────┤ │
│ │   Tab 根页：首页 / 工作台 / 我的智能体 / 我的 │
│ │   二级栈页：从右滑入，带返回按钮           │ │
│ └────────────────────────────────────────┘ │
│ ┌ 底部 Tab 栏（仅在栈顶为根页时显示）────────┐ │
│ │ 🏠首页  💬工作台  🤖我的智能体  👤我的      │ │
│ └────────────────────────────────────────┘ │
└──────────────────────────────────────────────┘
```

- **切 Tab**：重置页面栈为 `[tabId]`，无返回按钮，底部 Tab 栏常驻高亮当前项。
- **进入二级页**（如子智能体对话、完整报告、导师详情）：`pushPage(id)` 入栈，页面从右侧滑入，Header 左侧出现「← 返回」，底部 Tab 栏隐藏；`popPage()` 出栈返回上一层，直到栈顶重新是 Tab 根页为止。
- 与桌面版 `hideAllAppScreens()/openXxx()/backFromXxx()` 的命令式切换不同，移动端统一走 `pushPage`/`popPage`/`switchTab` 三个通用方法，避免每个页面都要单独写显示/隐藏逻辑。

## 6. 组件适配规则

| 桌面组件 | 移动端替代方案 |
| --- | --- |
| 智能体矩阵 5 列 grid（`.agent-grid`） | 横向 `overflow-x:auto` 卡片行，卡片定宽，滑动浏览 |
| 成就徽章 2 列 grid（`.badge-grid`） | 保留 2 列（信息密度尚可），或按屏宽降为 1 列 |
| 报告页左侧目录 + 右侧正文双栏 | 顶部横滑 Chip 锚点导航（`scrollIntoView`）+ 单列正文，取消侧栏 |
| 差距诊断表格 `.gap-table`（5 列表格） | 改为纵向卡片列表，每条差距一张卡：要求 / 现状 / 差距 / 建议 / 关联维度 |
| 导师工作台左列表 + 右详情双栏 | 拆成两级页面：学生列表页 → 详情页（返回上一级） |
| 桌面 Modal 居中弹窗（登录/示例报告） | 改为底部滑入的全屏/半屏 Sheet，贴合移动端手势习惯 |
| 快捷回复 Chip 组遇多选项换行拥挤 | 允许横向滚动 `overflow-x:auto`，不强制换行 |
| 触控目标 | 按钮/Chip/卡片可点击区域统一 ≥44px，间距加大 |

- 长期跟踪与子智能体：`SUBAGENTS`、`SUBAGENT_CHATS`、子智能体对话引擎（`addSubMsg`/`addSubQuestionChips`/`beginSubAgentChat`）

## 8. 验证计划

用 Playwright 模拟以下视口做冒烟测试，并截图核对无遮挡/溢出：

- iPhone 12/13 · 390×844
- iPhone SE · 375×667（最窄基准）
- 常见 Android · 412×915

验证链路：4 个 Tab 切换 → 工作台对话建档全流程（含画像 Sheet）→ 15 维解析 → 方案选择 → 行动计划 → 我的智能体 Tab → 5 个子智能体对话 push/返回 → 完整报告页锚点导航 → 导师身份下学生列表/详情 push/返回 → 登录 Sheet 全身份路径 → `?frame=1` 手机外壳显示/隐藏。
